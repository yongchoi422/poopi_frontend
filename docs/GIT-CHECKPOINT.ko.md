# 2026-10-14 개발 소스 Git 체크포인트

사용자가 지금까지의 개발 작업을 GitHub에 올리고 기본 브랜치에 합치도록 요청했다. 저장소 기본 브랜치는 `master`이며 `main`으로 이름을 바꾸지 않는다.

## 포함하는 작업

- 홈페이지, 영상 배너, 구매/관리/내 SOULI/백서, MetaMask 연결과 구매 복구 흐름.
- Base 판매·관리·LP 실험 계약 소스, 테스트, 공개 주소/배포 설정과 검증용 자료. LP 실험 코드가 있다는 사실은 LP 실행이나 잠금 완료를 뜻하지 않는다.
- 최소 API, Azure 설정, 빌드·검사·수동 릴리스 준비 스크립트, 개발 결정과 인계 문서.
- `output/game/`의 3D 방·광장·방치형 실험과 대기방: 원본 코드, 의존성 잠금 파일, 모델, 검증 화면과 규칙 테스트. 아직 공개 구매 흐름과 통합하지 않은 개발 결과다.
- 서비스가 실제 사용하는 `public/media/`의 영상·포스터·티저. 영상 제작 스크립트·프롬프트·SVG 입력·전달 목록도 보관한다.
- `tmp/commercial-v2/`, `tmp/mainnet-pilot/`의 검토·배포 작업대와 공개 체인 설정. 기존 검증 스크립트가 이 경로를 참조하므로 보존한다. 생성된 ZIP은 제외한다.
- `tmp/checkout-review/`, `tmp/game-teaser/`, `tmp/soul-review/`의 로컬 검토·이미지 재생성 도구.

## 로컬에 남기는 자료

`node_modules`, `.env`, 로그, DB, 클라우드/지갑 비밀 설정, 운영 계정 화면 캡처, 일별 X 운영 기록, 중복 검토 패키지와 PDF 출력물은 Git에 포함하지 않는다. 약 3GB의 제작 영상·중간 이미지·ZIP은 로컬 미디어 라이브러리에 유지한다. 서비스용 선정 영상은 `public/media/`에 별도로 포함되어 있다. 제외는 삭제가 아니며 기존 파일은 그대로 둔다.

마케팅 검토 HTML의 전체 영상 자료실은 원본 미디어가 있어야 열린다. Git만 새로 받은 경우 홈페이지용 6편은 바로 사용할 수 있지만 제작 영상 전체 자료실까지 복원되는 것은 아니다.

## 새 컴퓨터에서

루트 README의 Node 24 설치·`npm ci` 절차를 따른다. 서버와 계약은 각각 별도 lockfile을 가진다. 3D 실험도 해당 폴더에서 설치한다. `npm test`는 로컬 검사이며 라이브 지갑 서명이나 판매 재개를 수행하지 않는다.

과거 실행 영수증과 클라우드 배포 도구는 `logs/`에 남아 있다. 해당 로그를 읽는 일회성 운영 검사는 원본 기록이 별도로 필요할 수 있다. 일반 실행·빌드·로컬 테스트와 공개 판매 설정은 Git 소스에 포함한다. 클라우드 배포에는 별도 Azure 로그인과 배포 도구 설정이 필요하다.

이번 Git 동기화 자체로 웹사이트 재배포, 판매 조건 변경, 지갑 서명, 자산 이동을 수행하지 않는다. 과거 문서의 체인 잔액·재고·배포 상태는 각 문서에 기록된 시점의 값이다.

## 이번 검증

- 루트 전체 검사: 프런트 로직, 서버 23개 테스트, Vite production build, Docker 실행 파일 묶음 검사 통과.
- 로컬 계약 테스트 153개 통과. 3D 게임/대기방 규칙 테스트 43개 통과.
- Git index에서 별도 빈 폴더로 소스를 복원하고 루트/서버 의존성을 `npm ci`로 설치한 뒤 전체 웹 검사를 다시 통과했다.
- 새 체크아웃의 줄바꿈 변환으로 기존 검증 해시가 깨지지 않도록 Solidity 및 명시적으로 해시를 고정한 입력 파일의 바이트를 `.gitattributes`로 보존한다. 처음 실행하는 환경에서도 로그 폴더를 생성하도록 검사/읽기 스크립트를 보완했다.
- 이 검사는 독립 외부 감사나 추가 메인넷 결제 테스트가 아니다. 원본 vendor 소스와 제작 기록의 기존 공백은 의미/해시 보존을 위해 일괄 포맷하지 않는다.
