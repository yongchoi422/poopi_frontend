# LP 전용 판매·영구 잠금 후보 검증

2026-10-02 · 로컬 구현/실패 시험 · 공개 배포/실판매/독립 감사 아님

**후속 사용자 결정:** 이 후보는 현재 출시 경로에서 제외하고 연구/검증 기록으로 보존한다. 사용자는 treasury 인출 후 수동 LP 공급과 **2-of-3 Safe** 방향을 최종 선택했다. [최신 운영 계획](MANUAL-LP.ko.md)을 따른다. 아래 결과는 LP 전용 후보의 시험 결과이며 수동 LP 또는 실제 Safe 연동을 검증한 결과가 아니다.

## 결론과 범위

`contracts/src/SouliLpSale.sol`과 `SouliPermanentLpLock.sol`을 새로 구현했다. **새 LP 검증 27개를 포함한 계약/클라이언트 68개, 실제 Base 포크 9개 경로, 프런트 10개 스크립트와 서버 23개 테스트·빌드·패키지 검사를 통과**했다. 기존 Sepolia의 treasury 인출 계약은 그대로이며 이 후보로 교체하거나 새 주소를 공개하지 않았다. 메인넷 구매는 계속 비활성이다.

정상 거래와 실패 후 자금 보존을 검증한다. **항상 LP 개설에 성공한다는 보장은 없다.** 기존 풀 가격이 약정 범위를 계속 벗어나거나 원본 토큰/DEX가 동작하지 않으면 준비금이 계약에 계속 남는다. 환불·관리자 회수 기능이 없는 구조이므로 이 지연은 핵심 출시 조건이다. 아래 테스트 성공만으로 실판매를 열지 않는다.

## 구현한 규칙

- 고정 ETH 단가, 전체 판매 한도, 시작 시각, 가격 허용 범위, 토큰/DEX/페어/잠금 주소, 약관 해시는 배포 후 바꿀 수 없다. Base 메인넷에서는 원본 토큰·공식 v2 라우터/팩토리 주소와 관측한 코드 해시도 강제한다. 테스트 체인은 별도 모의 계약을 허용한다.
- `Preparing → Funding → Ready → Live`이며 일시중지는 별도 표시다. 첫 개시 전에 구매 재고 전량과 LP 재고/가격 대응 준비분을 모두 실제로 입고해야 한다.
- 구매는 같은 거래에서 정확한 SOULI를 보낸다. 지급 실패, 수수료 차감, 잘못된 금액, 만료 견적, 재고 부족은 ETH와 집계도 전부 되돌린다. 가스비는 별도다.
- LP 지원은 토큰 지급 없는 별도 입금이다. 구매/지원 각각을 기록하며 목표를 넘는 입금은 거래 전체를 거절한다. 소수 wei 지원 때문에 구매 1개보다 작은 잔액이 남으면 지원으로 정확히 채울 수 있다. 직접/강제 ETH 입금은 판매나 목표 진행률에 포함하지 않는다.
- 관리자는 일시중지 후 **입고 기록이 있는 미판매 구매 재고만** 회수할 수 있다. LP 준비 토큰·판매/지원 ETH·LP 지분의 회수, 임의 승인/호출, 업그레이드, 성공 구매 환불 함수는 없다. 소유권을 다른 주소로 옮겨도 이 제한은 같다.
- 관리자가 구매를 중지해도 이미 개시한 회차의 지원/목표 달성/LP 실행을 독점 차단하지 못한다. `finalize()`는 누구나 호출할 수 있고 가스는 호출자가 부담한다. 자동 실행기 서비스는 아직 연결하지 않았다.
- 성공하면 **집계된 목표 ETH 전액**이 페어의 WETH가 된다. LP는 관리자 지갑을 거치지 않고 새 잠금 계약으로 직접 발행된다. 발행 수량·수령지·실제 잔액 변화가 맞지 않으면 전부 되돌린다. 남은 SOULI 준비분과 강제 입금 잔액은 인출할 수 없으며 투입액으로 표시하지 않는다.
- 잠금 계약에는 소유자·승인·전송·업그레이드·출금·selfdestruct가 없다. 잠금 기간이 만료되는 구조가 아닌 **영구 잠금 후보**다. v2 수수료도 LP 지분에 남으므로 운영비로 꺼내지 못한다. 기존 제3자의 LP나 이후 다른 제공자의 LP까지 잠기는 것은 아니다.

LP 준비분은 **입고 때부터 관리자 회수가 불가능**하다. 배포 주소/조건 착오도 긴급 인출로 복구하지 못한다. 메인넷 입고 전 별도 검토가 필요한 이유다. 임의로 토큰·ETH를 보내지 말고 지정한 입고/지원 함수를 사용해야 한다.

## 이번 구현에서 고친 실패 경로

1. **빈 풀에 먼지를 보내고 `sync()`를 먼저 실행하는 방해:** 일반 라우터는 한쪽 준비금만 있는 초기 풀에서 실패할 수 있었다. 아직 LP 발행량이 0이면 직접 WETH 포장·정확한 두 자산 입고·첫 LP 발행을 한 거래에서 실행하도록 했다. 기존 먼지까지 포함한 결과 가격이 고정 허용 범위 안이어야 한다. 가격을 크게 왜곡하는 선행 입금은 계속 거절한다.
2. **기존 풀 비율 때문에 ETH 일부가 돌아오는 경우:** 목표 ETH 전액과 고정 가격 범위를 기준으로 필요한 SOULI를 계산하고, 소량의 별도 SOULI 준비분을 사전 입고한다. ETH 최소 투입량은 목표 전액이다. 부족분·반올림·가격 범위를 검증하며 일부만 들어간 상태를 성공으로 처리하지 않는다.
3. **라우터 성공 반환만 믿는 경우:** 판매 계약과 페어의 실제 자산 변화, 잠금 주소의 LP 증가량, 보수적으로 계산한 최소 LP 수령량을 함께 대조한다. LP 수령지가 틀리거나 과소 발행·허위 반환이면 전체 거래가 취소된다.

기존 풀은 거래 직전 준비금만을 공정 가격으로 신뢰하지 않는다. 미리 고정한 가격과 비교하며 허용 범위 밖이면 멈춘다. [Uniswap 유동성 공급 지침](https://developers.uniswap.org/docs/protocols/v2/guides/providing-liquidity), [공식 페어의 mint/sync/skim 구현](https://github.com/Uniswap/v2-core/blob/master/contracts/UniswapV2Pair.sol)을 기준으로 검토했다.

## 테스트용 경제 조건

시험은 1,000 SOULI 판매 한도, 개당 0.000001 테스트 ETH, 목표 0.001 테스트 ETH, 가격 허용 범위 0.5%로 수행했다. 이는 실판매 가격이 아니다. 계약이 허용하는 최대 오차는 1%이며 배포 시 고정한다.

사용자가 제시한 15M FDV / ETH 쪽 50k USD의 기준 계산에 **이번 0.5% 시험 설정**을 적용하면 다음과 같다. USD/ETH 기준 시점과 실가격은 여전히 미확정이다.

| 용도 | 기준 SOULI |
|---|---:|
| 구매용 최대 재고 | 700,000 |
| 목표 가격의 LP용 재고 | 700,000 |
| 추가 LP 가격 대응 준비분 | 3,500 |
| 사전 입고 합계 | 1,403,500 |

첫 새 풀은 기본 700,000개를 사용하고 준비분은 남는다. 기존 풀에서는 고정 가격 범위와 실제 수량에 따라 달라진다. 미사용 준비분은 운영자 회수나 운영비로 돌리지 않는다. 이 비가역적 잔여 토큰 정책·영구 잠금·0.5% 선택은 후보 구현의 정책이며 메인넷 최종 조건으로 승인된 사실이 아니다.

## 실행과 증거

```powershell
npm.cmd run test:sale
npm.cmd run test:sale:lp-fork
npm.cmd test
```

포크는 기본 Base 블록 52,067,385를 읽어 **로컬 Hardhat 31337**에 복제한다. 원본 Base에는 쓰기·송금·배포를 하지 않는다. `BASE_READ_RPC`, `BASE_FORK_BLOCK`으로 다시 시험할 수 있지만 새로운 블록에 이미 페어/다른 상태가 있으면 결과를 별도 검토한다. 앞의 `test:sale`로 최신 아티팩트를 컴파일한 뒤 실행한다.

- `contracts/test/lp-sale.test.mjs`: 새 LP 후보의 정상/실패 검증. `LpFixtures.sol`은 시험 전용 가짜 DEX/악성 행동이며 배포 대상이 아니다.
- `logs/sale-checks/lp-contract-tests.xml`: 기존 판매/클라이언트를 포함한 최종 회귀 테스트 기록.
- `logs/sale-checks/lp-sale-fork.json`: 실제 SOULI + 공식 Base Uniswap v2 **9개 경로 통과**. 공개 거래 0건. 기록 속 sale/pair/lock 주소는 로컬 시험 주소다.
- 포크 관측 가스: 배포 약 5,633,747, 첫 LP 실행 약 505,520, 기존 풀 공급 약 385,072 gas. ETH/달러 비용 견적이 아니며 실제 환경에 따라 달라진다.

## 출시 전에 남은 사항

**가장 큰 잔여 위험은 안전한 중지가 장기 지연이 될 수 있다는 점**이다. 외부 풀이 허용 가격으로 돌아오지 않거나 큰 선행 입금/원본 기능 문제를 복구할 수 없으면 자동 실행도 성공하지 못한다. 관리자에게 우회 출금/임의 가격 변경을 주는 방식으로 해결하지 않았다. 즉시 지급·환불 없음·고정 가격·공개 DEX를 동시에 선택한 데 따른 제약을 판매 전에 공개하고 최종 출시 정책을 검토해야 한다.

다음은 후보 바이트코드/조건을 고정한 별도 Base Sepolia 경로, 독립 구매자와 실제 2-of-3 Safe, 관리자 키 분리, 지갑 복구/중복 승인, LP 잔액/전체 지분 대비 잠금 비율 UI, 자동 실행기 장애/가스 모니터링, 원본 관리자 권한 대조, 독립 보안 검토다. Sepolia에 테스트 DEX가 필요하면 공식 Base 메인넷 풀과 혼동되지 않도록 명확히 표시한다. 기존 `/testnet/`의 treasury 출금 성공 기록은 새 LP 구조 검증으로 재사용하지 않는다.
