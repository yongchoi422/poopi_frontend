# 구매 UX 최종 검토 · 2026-10-04

범위: 홈 게임 티저와 `/buy/`의 수량 선택 → 지갑 연결 → 검토 → 서명 요청 → 영수증 복구 → 수령 화면. 실제 판매 조건·계약·관리자·가격·LP 정책은 이번에 변경하지 않는다. 이미 열린 판매를 다시 개방하거나 실제 자산을 이동하지 않는다.

## 수정한 점

1. 게임: 마을 전경 대신 기존 원본 SVG와 게임 3D 변환 모듈로 만든 캐릭터 한 개. `Game in development`, `3D character preview · Sample soul` 명시. 방이나 게임 출시를 암시하지 않는다. 공개 페이지는 46.7KB PNG를 사용하며 Three/WebGL 실행 비용을 추가하지 않는다.
2. 지갑: 연결 주소·실제 연결 네트워크·Disconnect를 주문 카드에 표시. 지갑 변경/해제 시 기존 견적과 동의가 초기화된다. 연결 중 버튼 문구도 진행 상태를 표시한다.
3. 재접속: 대기 중인 구매를 저장한 채 새로고침하거나 연결이 끊겨도 `Reconnect MetaMask`로 복구한다. 네트워크가 다르면 전환 동선을 제공한다. 재연결 자체는 새 결제를 요청하지 않는다. 잘못된 형식의 대체 해시는 확인 버튼을 활성화하지 않는다.
4. 마지막 확인: Token subtotal, 예상 가스비, 예상 합계, 수령 지갑을 구분. `Continue to MetaMask`는 별도의 최종 지갑 승인이 남았음을 알린다. 확인 화면에도 개발 중/자동 환불 없음/재판매 미보장/50:50 수동 계획/LP 미생성 상태를 간결하게 표시한다.
5. 외형: 레벨은 새 inscription에 대한 안내임을 명시하고, 기존 보유자가 추가 구매하면 현재 소울이 바뀔 수 있음을 짧게 안내한다. 예시 이미지가 확정 상품이거나 구매마다 새 캐릭터가 생긴다고 말하지 않는다.

## 검증 근거

- `tmp/checkout-review/`: 실제 BuySouli 컴포넌트, native-sale 클라이언트, V2 계약을 사용한 폐기 가능한 로컬 체인 31337. Base 자산·MetaMask·개인키를 사용하지 않는다. 공급/구매는 테스트 자산이다. 브라우저 자동화로 계정 연결, 부족 잔액, 서명 거절, 대기 영수증, 연결 해제·새로고침·재연결, 잘못된 네트워크, 견적 검토 중 지갑 해제를 확인했다.
- 새로고침 후 재연결로 이전 1개 구매를 복구했으며 이후 새 payment 요청은 0. 사용자 지갑 서명과 실제 새 메인넷 결제를 검증한 것은 아니다. 기존 실제 메인넷 구매 기록은 HANDOFF 1.56 및 공개 영수증에 별도로 남아 있다.
- native-sale 19개 + V2/관리 클라이언트 16개 회귀 검사 통과. 수량/잔액/네트워크/견적 만료/거절/중복 요청/영수증·대체 거래/저장 실패/현재 V2 재입고 조건 등을 검증한다. 루트 검사·서버 검사·생산 빌드도 실행한다.
- 실제 공개 재고를 읽는 구매페이지에서 레벨 4 선택/외형 변경 시 수량 유지, 현재 재고 초과 직접 입력 차단, 재고 부족 레벨 5 비활성화 확인.
- 320/390/768/1440/2560px 구매 레이아웃과 소형/모바일/와이드 게임 티저 확인. 상세 증거는 `logs/sale-checks/checkout-final-*`, `game-teaser-*`.

## 출시·마케팅 표현

현재 판매 대상은 Base의 원본 SOULI 토큰과 inscription이다. 게임은 개발 중이다. 판매 대금은 팀이 관리하는 수동 50:50 계획이며 실제 LP·1년 잠금은 아직 생성되지 않았다. 첫 140만 개는 초기 재고 목표이며 계약의 누적 판매 한도는 420만 개다. 공개 수량은 최신 체인 상태를 따른다.

이번 검토는 구매 UI/동작과 기존 회귀 검증이다. 외부 독립 감사나 모든 휴대폰/MetaMask 버전에 대한 실기기 검증으로 표시하지 않는다. X 홍보는 공식 `/buy/`와 현재 제공 기능을 기준으로 작성하며 아직 만들지 않은 게임·LP·잠금을 완료된 기능으로 표현하지 않는다.
