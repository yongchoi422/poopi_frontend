# SOULI 게임 기획 통합 검토 — 내 소울의 방에서 작은 세계로

2026-10-03 · 내부 분석 및 제안 · 사용자 최종 채택 전

**후속 사용자 동의(2026-10-03):** 작은 dot도 충분히 재미있게 만들기, 원본 외형이 달라져도 생활 기록과 추억 이어가기, 오래 비워도 편안하게 복귀하기의 세 원칙에 동의했다. 다음 우선 작업은 기존 파스텔 배경에서 원본이 묻히는 문제를 해결할 대안 디자인 비교다. 아래 전체 구현 범위·상품·소유권 정책까지 확정됐다는 뜻은 아니다.

## 1. 판단

**첫 게임의 중심은 ‘내 원본 SOULI가 작은 현실 공간에서 스스로 살아가는 2D 관찰형 생활 게임’으로 좁히는 것을 권한다. 기존 마을과 비동기 협동은 그 생활이 바깥으로 이어지는 확장으로 남긴다.**

기존 기획의 강점은 원본 소유·성장·수집, 자동 생활, 함께 사는 세계다. 새 아이디어의 강점은 한 장면만으로 캐릭터의 매력과 다시 찾아올 이유를 설명한다는 것이다. 둘을 같은 비중으로 첫 화면에 넣으면 다시 복잡해진다. 방을 중심에 놓고 원본 갤러리와 동네가 이를 받치는 순서가 적합하다.

제품 설명 초안:

> 내 SOULI를 작은 방에 들여놓으면, 알아서 하루를 보낸다. 가끔 들러 무엇을 했는지 보고, 마음에 드는 순간을 남긴다.
>
> A little soul. A life of its own.

이 문서는 기존 결정을 자동으로 교체하지 않는다. 게임 코드·판매 조건·배포를 변경하지 않았으며, 테스트를 새로 실행한 보고서도 아니다. 현황은 아래 소스와 작업 기록을 대조한 결과다.

## 3. 지금까지 기획이 어떻게 바뀌었나

| 단계 | 중심 생각 | 남은 가치 | 지금 다시 볼 부분 |
|---|---|---|---|
| 초기 다섯 층 세계 | 하늘·지상·뿌리·수정·심연, 등대, 탐험·회복·방어 | 공간 확장과 발견의 가능성 | 세계가 커질수록 주인공이 작아지고 제작 범위가 커짐 |
| 성장·보존·수집 마을 | Dynamic 성장 → 좋아하는 모습 Stable 보존 → 주민 정착 | SOULI 원본을 가진 이유 | 보존 거래를 이해해야 첫 재미를 얻는 흐름은 무거움 |
| 자동 생활·협동 | 채집·건설 자동 진행, 동네 공동 정원과 보호 | 조작 없이 살아가는 느낌, 소속감 | 화면은 자동이지만 실제 목표는 재료와 공사 중심 |
| ETH 연동·저비용 구현 | 시장이 날씨를 바꾸고, 돌아올 때 진행 계산 | Base 정체성, 적은 서버 사용 | 매일의 재미를 가격 변동에 의존하면 생활이 좁아짐 |
| 생활 코미디 영상 | 진지한 원본과 커피·쿠션·알람 같은 사소한 사건 | 기억하기 쉽고 공유하기 좋은 캐릭터성 | 광고의 고정 연출을 플레이 상태로 바꿔야 함 |
| 이번 방 아이디어 | 한 소울의 하루·성격·소품·추억 | 애착을 가장 가까이서 전달 | 단순 영상 반복을 넘는 지속 상태와 발견 구조 필요 |

이 변화는 ‘완전히 다른 게임을 처음부터 시작’하는 것보다는 **이미 원했던 자동 생활을 실제 게임의 주인공으로 만드는 재집중**에 가깝다. 기존 상세 기획도 다섯 층과 등대 구성을 고정 조건으로 두지 않고 새 핵심 루프에 맞춰 바꿀 수 있다고 명시한다.

### 우선순위가 달라진 과거 제안

- BTC 기준은 후속 사용자 결정인 **ETH 기준**으로 바뀌었다.
- Start/Collect/Contribute를 기본 조작으로 삼던 안은 **자동 생활·자동 건설**로 바뀌었다.
- 상시 서버 순회는 **요청 시 계산과 5분 체크포인트**로 바뀌었다.
- Google 운영·Azure 이전 보류 문구 뒤에 실제 Azure 전환 기록이 있다. 오래된 미배포 문구를 현재 상태로 인용하지 않는다.
- USDC 토큰 판매·예약 지급·자동 LP·2-of-3 등은 후속 판매 논의로 변경됐다. 게임 기획에서 과거 판매안을 다시 확정하지 않는다. 현재 판매 준비는 Base ETH 즉시 지급, 수동 LP, 세 등록 지갑의 개별 관리 방향이며 최신 판매 문서와 개발 채팅을 따른다.
- 장식 매출 우선은 초기 PD 제안이다. 후속 사용자 의도는 **SOULI 판매를 먼저 준비**하는 것이다. 가구·테마 판매는 장기 후보로 남긴다.

## 4. 기존 게임 기획 전체를 기능별로 정리

| 축 | 기존 내용 | 방 중심 게임에 대한 제안 |
|---|---|---|
| 원본 | 실제 ERC20i SVG, 원본 픽셀·색·형태 보존 | 그대로 유지. 생활 동작은 원본 바깥의 연출로 구현 |
| 입문 | 지갑 없는 무료 체험, 홀더 자기 원본 정착 | 즉시 방 구경 → 내 원본 데려오기. 연결을 첫 장면의 조건으로 두지 않음 |
| 성장 | Dynamic의 온체인 모습 변화와 게임 Memories 구분 | 외형의 변화와 생활의 성장을 분리. 성격·버릇·추억은 플레이로 생김 |
| 수집 | Stable 원본 보존·갤러리·여러 주민 | 갤러리는 유지. 첫 방은 한 명으로 충분하게, 여러 명은 이후 관계 확장 |
| 직업 | Explorer·Guardian·Healer | 필수 편성 대신 탐색 좋아함·정리 좋아함·돌보기 좋아함 같은 생활 경향으로 전환 검토 |
| 자원 | Supplies·Glowstones·Dew·Memories | 첫 화면의 수량 강조를 줄임. 가구 발견·생활 흔적·앨범이 진행을 설명 |
| 건설 | 가로등 → 쉼터 → 갤러리, 공동 정원 | 방의 기본 생활을 먼저 완성. 마을 공사는 후속 공동 목표로 보존 |
| 방치 | 로컬 2시간, 문서상 12/24시간 확대 실험안 | 생활 사건·기억과 생산 상한을 분리. 장기 미접속도 편안하게 복귀 |
| 시장 | ETH 날씨, 비·안개·빛 폭풍 | 창밖과 일부 사건의 변형으로 유지. 햇빛·휴식·기본 발견이 매수나 상승장에 종속되지 않게 함 |
| 협동 | 최대 32개 집의 비동기 기여·공동 보호 | 이웃 방문·공동 창가·동네 등불 등 생활과 연결되는 후속 단계 |
| 미술 | 큰 2D 도트 세계, 원본 대비·가독성 | 현실 소품을 2D로 표현한 작은 무대. 원본과 배경의 재질 차이를 의도적으로 사용 |
| UI | 영어, 최소 텍스트, 큰 장면, 상세는 눌러 보기 | 방·오늘의 한 장면·작은 앨범/꾸미기 진입 중심 |
| 상품 | 집·계절 장식·후원자 꾸미기·확장팩 후보 | 외형에 더해 행동과 사건을 제공하는 소품/방 테마 후보. 기본 행동은 충분히 무료 제공 |
| 자산 경제 | SOULI는 외부 자산, 게임 재료는 환전 불가 | 코미디 사건에 실제 토큰 수익·손실을 붙이지 않음 |
| 서버 | Base 원본, MetaMask 인증, Azure 저장, 요청 시 정산 | 기존 분리 구조 유지. 프레임별 생활 연출에 거래나 서버 틱을 붙이지 않음 |
| 장기 목표 | 층 확장·수집·마을 성장·상품 운영 | 방의 애착 → 다양한 하루 → 이웃 → 작은 세계 순서 |

## 5. 무엇이 구현돼 있고 무엇이 없는가

| 구분 | 확인 상태 | 이번 방향에서의 의미 |
|---|---|---|
| 실제 SVG·dot 표시·원본 종류 구분 | 프런트 코드와 기존 검수 기록 있음 | 가장 중요한 재사용 자산 |
| 자동 채집과 세 개인 공사 | sanctuary.mjs에 구현 | 새 사건 시스템의 재료가 되지만 그대로는 생활 게임이 되지 않음 |
| 로컬 저장·복귀 | souli-sanctuary-v1, OFFLINE_MS 2시간 | 여러 날의 생활 기록은 새 설계가 필요 |
| 일지 | 최근 최대 12개 텍스트 기록 | 12개 코미디 사건, 영구 사진 앨범, 재연 시스템이 구현됐다는 뜻이 아님 |
| ETH 날씨·공동 보호 | 프런트·서버 코드와 구현 문서 있음 | 생활의 분위기와 동네 확장에 활용 |
| 서명 인증·개인 집·공동 정원 | 서버 구현·검증 기록, 공유 기능은 초대 범위 | 공개 전체 사용자 운영 검증과 구분 |
| 최소 API와 정적 웹 | Azure 전환·공개 배포 기록 있음 | ‘아직 서버가 전혀 없다’는 오래된 설명은 현재와 다름 |
| Stable 보존 | 설명 UI와 계약 조사·포크 검증 기록 | 소비자용 보존 이전 흐름이 완성된 것과 구분 |
| 현실적인 실내·소품 행동·성격·앨범 | 새 구현 필요 | 이번 게임 방향의 핵심 작업 |
| 실시간 동접 아바타·친구 초대 | 미완성/후속 범위 | 배경 샘플을 실제 이웃으로 표시하지 않음 |
| 영상 80편 | 생성 단편과 파일 목록 있음 | 게임 내 사건 80개가 구현된 상태는 아님 |
| 구매·관리 | 테스트넷 검증과 메인넷 준비 진행 기록 | 게임 장면 변경과 독립적으로 재사용. 이번 분석은 판매 완료 검증이 아님 |

현재 코드는 1분을 한 작업 단위로 계산하고 정해진 재료를 쌓아 세 공사를 자동 완성한다. 이 구조의 주된 변화는 공사 전후다. **한 번 공사를 다 본 뒤에도 궁금할 개인적 생활 변화**가 상대적으로 약한 지점이 새 아이디어가 해결할 문제다. 이는 코드와 콘텐츠 구조에 대한 판단이며 실제 이용자 이탈 원인을 측정한 결과는 아니다.

## 6. 세 방향의 비교

아래 평가는 SOULI 자료에 근거한 제품 판단이며 매출 예측이나 플레이테스트 결과가 아니다.

| 기준 | 기존 수집·건설 마을 | 방 중심 관찰 생활 | 방 중심 + 이후 동네 확장 |
|---|---|---|---|
| 10초 안에 매력 전달 | 세계와 규칙 설명이 필요 | 한 사건으로 전달 가능 | 방을 먼저 보여주면 가능 |
| 광고와 실제 플레이의 연결 | 현재 영상과 장소·행동 차이가 큼 | 커피·쿠션 등 직접 연결 | 초기에는 방과 동일 |
| 한 소울에 대한 애착 | 주민 수와 공사가 관심을 분산 | 개인 버릇과 일상을 가까이 관찰 | 개인 애착 위에 관계가 더해짐 |
| 장기 목표 | 확장·건설이 비교적 명확 | 사건이 반복되면 빨리 소진될 위험 | 생활·수집·관계로 확장 여지 |
| 초기 제작 범위 | 지역·공사·경제·협동의 동시 부담 | 작은 공간으로 줄지만 연출 품질 필요 | 단계를 지키면 관리 가능 |
| 기존 기반 재사용 | 높음 | 지갑·원본·저장·날씨는 재사용, 장면은 새로 만듦 | 기술 기반과 장기 세계관을 모두 활용 |

권고는 세 번째다. 다만 **첫 출시부터 방과 마을을 동시에 완성한다는 뜻은 아니다.** 방 하나만으로 방문 이유가 생기는지 먼저 확인한다. 협동은 사용자가 원했던 장기 가치이므로 삭제하지 않고 순서를 뒤로 둔다.

참고할 경험도 달라진다. 과거 상업적 방치 RPG 조사는 자동 진행·짧은 접속·눈에 보이는 변화를 배우는 데 유효하다. 이번 핵심은 관찰과 애착이므로, 화면 감상·앨범·꾸미기를 제공하는 [Neko Atsume 공식 안내](https://www.nekoatsume.com/sp/en/about.html), 장식에 따른 방문·사진·우정을 설명하는 [Usagi Shima 공식 소개](https://usagishima.net/presskit/), 다른 일을 하면서 자동 농장을 보는 [Rusty’s Retirement 공식 상점](https://store.steampowered.com/app/2666510/Rustys_Retirement/)가 더 직접적인 참고다. 이 유사성은 SOULI의 흥행을 증명하지 않는다.

## 7. 영상의 매력을 게임으로 옮기는 방법

직접 본 01편은 커피와 주변 물성이 크게 움직이고, 16편은 원본 자체가 쿠션 속으로 내려가며, 80편은 소울 곁의 알람이 슬리퍼로 떨어진다. 얼굴을 바꾸지 않아도 위치·가림·소품 반응으로 이야기를 전달할 수 있다는 공통점이 있다.

다만 모든 게임 사건에서 소울이 제자리에 있고 소품만 움직이면 무대의 관객처럼 느껴질 수 있다. **원본의 형태를 유지하는 것과 캐릭터가 행동하지 않는 것은 별개다.**

한 사건을 다음 여섯 요소로 만든다.

1. 의도: 커피를 마시려고 잔 쪽으로 간다.
2. 준비: 받침을 밀거나 자리를 신중하게 잡는다.
3. 작은 어긋남: 커피가 잔 옆에 떨어진다.
4. 반응: 잠시 멈춘 뒤 몸 전체가 아주 조금 기울거나 뒤로 물러난다.
5. 흔적: 바닥의 커피 자국, 옆으로 밀린 잔이 남는다.
6. 후속 변화: 다음에는 잔을 더 가까이 가져오지만 또 다른 일이 생긴다.

모든 사건이 실패 농담일 필요는 없다. 평범하게 잘 쉬는 시간과 조용한 성공이 있어야 소울의 생활이 계속되는 느낌이 난다. 잔잔한 일상 사이에 짧은 코미디가 생기게 한다.

### 화면과 움직임

- 기본은 고정된 2D 방 전체. 선택한 사건은 같은 공간에서 잠깐 가까이 보여준다. 영상 하나가 끝날 때마다 별도 배경으로 이동시키지 않는다.
- 방은 사람의 평범한 소품이 소울에게 크게 느껴지는 책상·창가·쿠션의 작은 생활권으로 잡는다. 작은 인간용 판타지 집만 만들면 영상의 크기 차이에서 오는 재미가 약해질 수 있다.
- 종이·목재·천의 질감과 접지 그림자, 앞뒤 가림, 낮과 밤의 빛을 사용한다. 미리 렌더링한 배경과 레이어로도 가능한 표현이며 3D 엔진을 전제로 하지 않는다.
- 원본의 실루엣·색·픽셀을 유지한다. 점에 눈과 팔을 만들지 않는다. 의미가 불명확한 SVG 도형을 얼굴·효과라고 추측해 분해하지 않는다.
- 이동·작은 도약·멈춤·몸 전체 기울임과 소품 반응을 쓴다. 생활 중의 의도는 얼굴 애니메이션보다 동선과 타이밍으로 읽히게 한다.
- 모바일에서 방 전체를 무조건 축소하지 않는다. 소울과 사건을 알아볼 수 있는 카메라 구도를 별도로 검증한다.

## 8. 구경을 넘어서 게임이 되는 생활 구조

**공간을 마련함 → 소울이 행동을 선택함 → 작은 사건이 생김 → 흔적과 취향이 남음 → 다음 방문에서 알아봄 → 가끔 공간을 바꿈.**

플레이어는 소울을 매번 지휘하지 않고 환경에 영향을 준다. 가구를 놓는 위치, 창가에 둘 물건, 앨범에 남길 순간 정도가 선택이다. 아무것도 누르지 않아도 기본 생활이 이어진다.

| 시간 규모 | 보여줄 변화 | 저장할 내용 |
|---|---|---|
| 지금 보고 있는 동안 | 이동·머뭇거림·잠·소품 반응 | 중요한 행동의 시작/결과만 |
| 다시 들어왔을 때 | 지난 시간의 대표 장면 하나와 방에 남은 흔적 | 사건 ID·결과·장면 재연에 필요한 상태 |
| 며칠 함께 지낸 뒤 | 자주 찾는 자리·같은 실수 뒤 달라진 준비·작은 버릇 | 선호·습관·경험 이력 |
| 더 오래 지낸 뒤 | 새 소품 행동·추억·이웃과의 관계 | 해금과 관계의 기록 |

성격은 처음부터 수치 패널 여러 개로 설명하지 않는다. 예를 들어 같은 소파를 보고 조심스럽게 앉는 소울, 바로 뛰어드는 소울, 쿠션 틈부터 조사하는 소울의 차이로 드러낸다. 원본 희귀도나 토큰 보유량이 지능·호감·기본 재미를 결정하지 않게 한다.

콘텐츠는 사건 템플릿 + 성향 + 소품 상태 + 이전 경험 + 시간대의 조합으로 고른다. 변형 수를 곱한 숫자를 독립 콘텐츠 개수로 홍보하지 않는다. 같은 결말에 캡션만 바꾸는 것은 새로운 경험이 아니다.

## 9. SOULI의 소유·성장과 애착이 충돌하지 않게 하기

‘한 마리를 들인다’는 감정적 설명과 토큰의 실제 규칙은 구분해야 한다. **1 SOULI로 참여한다는 방향이 토큰 1개마다 독립 캐릭터 1개가 발행된다는 뜻은 아니다.** 보유 inscription과 Dynamic/Stable 상태를 읽어 원본을 연결한다.

| 층 | 의미 | 권고 |
|---|---|---|
| 원본 정체성 | 체인에서 읽은 SVG·seed·extra·현재 보유 권리 | 현재 체인 상태가 기준 |
| 생활 프로필 | 이름·선호 자리·성격·버릇 | 게임 계정의 기록으로 관리하는 안을 우선 검토 |
| 추억 | 예전 모습과 사건을 담은 앨범 | 과거 기록으로 보관. 현재 자산 소유 표시와 구분 |

Dynamic 외형이 변해도 같은 생활 프로필이 이어지면 ‘내 소울이 달라졌다’는 경험으로 설명할 수 있다. seed만을 생활 기록의 키로 사용하면 원본 변화 때 추억이 사라질 수 있으므로 별도의 주민 프로필 식별자가 필요하다. 여러 Stable을 동시에 들일 때는 각 원본과 프로필의 대응을 별도로 설계한다.

Stable 보존은 실제 계약 조건을 충족하는 이전이며, 그림을 앱에서 영구 고정하는 버튼이 아니다. 현재 기능을 확인하지 않고 ‘한 번 사면 원본 모습이 영원히 고정된다’고 설명하지 않는다.

토큰을 이전하거나 보유 자격을 잃었을 때 무엇을 계속 이용할지는 출시 정책으로 정해야 한다. 제안은 **개인 방·앨범·생활 기록은 삭제하지 않고, 더 이상 보유하지 않은 원본의 활성 사용과 현재 소유 표시만 갱신**하는 것이다. RPC 장애나 지갑 연결 해제를 자산 처분으로 단정해 주민을 제거하지 않는다. 새 소유자에게 기존 이용자의 사적 앨범이 자동 이전되는 것으로도 가정하지 않는다.

작은 dot도 커피 잔 가장자리에 서거나 쿠션 틈에서 빛이 보이는 방식으로 같은 12개 기본 사건을 경험하게 한다. 높은 단계가 있어야 캐릭터다운 행동을 하는 구조는 기존 사용자 의도와 충돌한다.

## 10. 첫 버전 — 방 1개, 소울 1명, 소품 5개, 사건 12개

이 수량은 **감정과 제작 방식을 검증할 작은 버전의 범위**다. 장기 운영 콘텐츠가 충분하다는 의미는 아니다.

방은 햇빛과 비 오는 창이 있는 작은 생활 공간 하나. 소품은 커피 머신, 소파, 작업 책상, 화분, 우편함. 잔·쿠션·종이·시리얼은 각 소품에 속한 연출 요소이며 별도 가구 상품으로 세지 않는다.

아래 12개는 이번에 제안하는 게임용 사건이다. 기존 영상과 동일한 구현이나 이미 만들어진 콘텐츠가 아니다.

| # | 소품 | 사건 | 다음 방문에 남는 것 |
|---|---|---|---|
| 1 | 커피 머신 | 잔은 준비했지만 커피가 옆으로 떨어짐 | 작은 얼룩과 밀린 잔 |
| 2 | 커피 머신 | 전날을 기억해 잔을 옮겼는데 이번에는 이미 가득 찬 잔 | 잔을 먼저 확인하는 버릇의 첫 징후 |
| 3 | 소파 | 잠깐 기대었다 쿠션 사이로 내려감 | 기울어진 쿠션 |
| 4 | 소파 | 꺼내 둔 작은 방석 대신 다시 같은 틈을 고름 | 좋아하는 자리 기록 |
| 5 | 작업 책상 | 한참 준비하고 종이에 점 하나 찍음 | 첫 작품 한 장 |
| 6 | 작업 책상 | 종이를 정리하다 한 장이 머리 위 종이 지붕이 됨 | 작은 종이집 |
| 7 | 화분 | 물을 주려다 옆의 아주 작은 버섯을 먼저 발견 | 버섯 한 개 |
| 8 | 화분 | 새싹을 계속 관찰하다 큰 잎 그늘 아래서 잠듦 | 그늘을 쉬는 자리로 사용 |
| 9 | 우편함 | 엄숙하게 기다렸는데 시리얼 한 알 도착 | 작은 배송 기록 |
| 10 | 우편함 | 그 한 알을 정성스럽게 책상에 전시 | 소중한 물건 목록 |
| 11 | 커피 + 책상 | 커피 자국을 작품처럼 액자 옆에 세움 | 우연히 생긴 두 번째 작품 |
| 12 | 우편함 + 소파 | 새 쿠션보다 쿠션을 담았던 작은 상자에 들어감 | 상자 휴식 장소 |

1→2, 3→4, 5→11, 9→10처럼 이전 경험이 다음 행동에 영향을 주게 한다. 12개를 하루마다 무작위 순환시키기보다 작은 연속성을 만든다. 긴 미접속을 벌주거나 사건을 놓쳤다고 수집을 영구 막지 않는다.

영상 연결 근거: 01 커피, 16 쿠션, 38 종이 덮임, 40 새싹, 70 시리얼 우편함은 초기에 직접 응용할 수 있다. 06 토스터, 21 양말, 28 종이 자동차, 37 로봇청소기, 80 알람은 후속 소품이나 방 테마 후보다. 처음부터 모두 넣어 범위를 늘리지 않는다.

80편은 부엌·휴식·작업·밖에서 생기는 일·과장된 특별 장면으로 선별한다. 실제 채택 결과를 기준으로 가져온다. 예를 들어 01편의 초기 기획에 있던 과충전 반응이 채택 영상에서 똑같이 구현됐다고 가정하지 않는다.

## 11. 복귀와 서버 구조

‘계속 살고 있다’는 감정은 브라우저를 닫아도 서버가 매초 애니메이션을 계산해야 한다는 뜻이 아니다. 기존 요청 시 정산 구조를 활용할 수 있다.

- 접속 중에는 브라우저가 장면을 그린다. 사건은 시작 상태와 결과가 일치하게 재생한다.
- 복귀 시 마지막 체크포인트, 당시 배치된 소품, 생활 프로필, 규칙 버전, 경과 시간을 바탕으로 사건을 계산한다.
- 첫 버전은 긴 부재에도 대표 장면 1개와 소수의 요약만 준비한다. 수백 장의 밀린 팝업이나 매분의 행동 기록은 필요 없다.
- 오늘 배치한 가구로 어제의 사건을 만들어내지 않는다. 배치 변경 시점도 기록한다.
- 사건 ID·선택 시드·결과를 고정해 새로고침마다 같은 기간을 다시 추첨하지 않는다. 재연은 이미 정해진 사건의 장면을 보여주는 기능이다.
- 실제로 녹화한 영상이 아니면 ‘녹화본’이라고 부르지 않는다. 게임의 일지와 재연이라는 방식으로 일관되게 설명한다.
- ETH 관측 기록이 없는 과거 시간에는 실제 시장 날씨 사건을 지어내지 않는다. 평상시 실내 생활은 시장 데이터 없이도 성립한다.
- 장기 부재의 생활 요약과 현재 2시간 생산·협동 상한은 별도 규칙으로 설계한다. 상한이 끝났다고 캐릭터가 쓰러지거나 세계가 정지했다는 벌칙 연출을 하지 않는다.
- 초기 사건과 짧은 문장은 작성된 템플릿으로 충분하다. 매 접속마다 생성형 영상·LLM 호출을 요구하지 않는다.

이 구조는 기존 저비용 방향과 잘 맞지만 사건 저장·재연·기억은 새 구현이다. 기존 텍스트 일지 저장을 이름만 앨범으로 바꾸면 완료되는 기능이 아니다.

## 12. 마을·협동·ETH는 어떻게 남길까

방이 집이라면 마을은 집 밖이다. 첫 장면의 관심을 유지하면서 이후 문·창문·우편함을 통해 바깥 생활을 보여줄 수 있다.

예: 소울이 바깥 등불을 켜고 들어와 젖은 작은 우산을 두고 쉰다. 다음 날 이웃이 감사 표시로 시리얼 한 알을 보내온다. 다만 ‘다른 플레이어가 보냈다’는 설명은 실제 방문/기여 기록이 있을 때만 사용한다. NPC 사건은 NPC로 구분한다.

공동 보호는 경보와 실패 압박보다 마을의 작은 변화로 표현하는 안을 권한다. 기존처럼 자산·집을 잃지 않고, 접속하지 못한 사람이 이웃에게 민폐를 끼쳤다고 느끼지 않도록 한다. 실시간 멀티플레이보다 기존 비동기 기여 기반을 먼저 활용한다.

ETH는 창밖 비·빛·안개와 일부 하루의 분위기에 반영한다. Base 관련 방문 이벤트는 실제 소식을 활용하는 경우 사실 확인이 필요하다. 12개 기본 사건 대부분은 시장 방향과 무관하게 발생해야 한다.

## 13. 구매와 공유의 연결

무료 샘플로도 소울의 생활을 충분히 보여준 다음 자기 원본을 들이는 경험을 연결한다. 소울의 기본 생활이 만족스러워야 원본을 소유하고 싶은 이유도 분명해진다. 초기 SOULI 판매 준비는 별도 작업으로 유지한다.

가구는 나중에 ‘새로운 행동과 장면을 여는 소품’이 될 수 있다. 다만 첫 기본 5개와 생활의 재미를 모두 유료로 잠그지 않는다. 기본 제공과 자연스러운 해금으로 충분히 경험하게 하고, 검증 후 테마나 확장을 검토한다. 과거 문서의 가격 실험 범위를 이번 상품 가격으로 확정하지 않는다.

운영 매출과 원본의 가치를 혼동하지 않는다. 시장에서의 추가 매수는 그 자체로 운영사의 게임 매출이 아니다. 한 소울에 대한 애착을 목표로 잡는다면 계속 추가 구매를 해야 생활이 유지되는 규칙도 피해야 한다.

공유는 광고 → 실제 체험 → 자기 순간 저장의 흐름으로 만든다. 첫 단계는 사진 카드와 앨범, 그다음 실제 게임 사건의 짧은 클립 내보내기다. 게임 내부 2D 장면의 공유 품질을 따로 검증하며, 생성 광고 영상을 이용자 게임 녹화본으로 표시하지 않는다. 자동 SNS 게시를 기본 기능으로 넣지 않는다.

## 14. 위험과 확인할 질문

| 위험 | 왜 문제인가 | 먼저 확인할 것 |
|---|---|---|
| 예쁜 영상 플레이어가 됨 | 내 선택·시간·이전 사건이 아무 영향이 없음 | 가구를 옮기고 다시 방문했을 때 설명 가능한 변화가 있는가 |
| 12개 농담이 소진됨 | 결말을 안 뒤 볼 이유가 사라짐 | 버릇·흔적·연속 사건을 이용자가 알아보는가 |
| 소울이 소품 옆에 계속 멈춰 있음 | 무엇을 원하고 했는지 읽히지 않음 | 원본을 바꾸지 않은 동선·타이밍만으로 의도가 전해지는가 |
| 1 SOULI 체험이 빈약함 | dot 이용자를 사실상 배제 | dot과 큰 원본이 같은 사건을 즐길 수 있는가 |
| 원본 변화 때 애착 단절 | 추가 보유나 이전 후 다른 존재처럼 보임 | 생활 프로필·추억과 원본 변화의 관계가 이해되는가 |
| 사실적 배경과 픽셀의 불일치 | 캐릭터를 붙여놓은 것처럼 보임 | 접지 그림자·앞뒤 가림·소품 반응이 자연스러운가 |
| 너무 많은 생활 관리 | 편안한 방치가 집안일로 변함 | 며칠 안 들어와도 복귀가 부담 없는가 |
| 방·마을·상점 동시 확장 | 핵심 재미 확인 전 제작 범위가 커짐 | 방 하나의 관찰 경험이 먼저 성립하는가 |

## 15. 다음 개발 범위와 판단 기준

### A. 연출 검증

기존 원본 로딩·지갑·저장 기반을 재사용하고 비교용 방 장면을 만든다. 처음에는 한 방, 커피/쿠션/책상의 세 사건만 만든다. 실제 dot과 큰 공개 샘플로 각각 본다. 본격적인 가구 상점·마을 확장은 이 단계에 넣지 않는다.

완료 조건: 설명 없이 소울이 무엇을 하려 했는지 읽히고, 가림 뒤에도 같은 원본이며, 360/390px에서 사건과 캐릭터가 보이고, 반복해서 볼 때 타이밍이 어색하지 않다.

### B. 다시 찾아오는 생활 검증

방 1개·소품 5개·사건 12개, 사건 흔적·두세 가지 성향·복귀 대표 장면·기초 앨범을 연결한다. 새 저장을 별도 버전으로 두고 기존 마을 진행은 보존한다. 서버 저장을 붙일 때 사건 중복 생성, 시간 역행, 동시 기기, 오래된 소품 배치, 소유권 조회 실패를 검증한다.

완료 조건: 어제와 오늘의 차이를 사람이 구체적으로 말할 수 있고, 1일·3일·7일 부재 후에도 부담 없이 돌아오며, 새로고침으로 같은 시간이 다른 사건으로 바뀌지 않는다.

### C. 소규모 관찰 후 확장

먼저 5~10명에게 첫 체험을 보여주고, 가능하면 약 20~30명의 소규모 그룹을 일주일 관찰하는 안을 권한다. 이는 성공을 입증할 표본 규모가 아니라 사용성·콘텐츠 문제를 찾는 초기 실험이다.

- 아무 설명 없이 ‘얘가 무엇을 하려 했는지’를 말할 수 있는가.
- 보상이나 추가 구매 안내 없이 스스로 다시 들어오는가.
- ‘소울이 귀엽다’에서 더 나아가 ‘우리 애는 그 쿠션만 좋아한다’ 같은 개인적 기억을 말하는가.
- 실제 앨범 저장·재연·공유를 선택하는가.
- 점 형태 이용자와 큰 원본 이용자 사이에 기본 만족의 큰 차이가 생기는가.
- 며칠 비웠을 때 죄책감이나 밀린 일의 압박이 생기는가.

이후 재방문·앨범 사용·반복 사건 피로를 보면서 소품/방 테마와 이웃 방문을 확장한다. 과거 기획의 D1/D7 수치는 당시 내부 실험 문턱이며 새 장르의 검증된 기준이 아니다.

첫 판단은 ‘가구를 더 많이 만들어야 하나’보다 **이 작은 방에서 한 소울이 자기 생활을 하고 있다는 느낌이 드는가**다. 그 느낌이 약하면 콘텐츠 수를 늘리기 전에 행동의 의도·반응·기억을 고친다.

## 16. 채택 전에 남는 제품 결정

이번 권고안은 개인 방을 기본 화면으로 두고, 기존 마을을 후속 확장으로 두며, 성격·추억을 토큰 단계와 분리한다. 사용자의 최종 방향 결정 후 기존 상세 기획의 첫 화면·핵심 루프·개발 순서를 이 구조로 갱신하는 것이 맞다.

출시 전에 확정할 항목은 원본을 이전한 뒤의 활성 주민 이용 정책, 여러 Stable과 생활 프로필의 대응, 장기 부재 요약의 보관 범위, 기본 가구와 추가 상품의 경계다. 방의 재미를 검증하는 프로토타입은 이 모든 상업 정책을 먼저 확정하지 않아도 만들 수 있다.

현재 분석에서의 결론은 **내 방의 애착을 먼저 만들고, 원본 수집으로 깊이를 더하고, 이웃과 마을로 넓히는 순서**다.
