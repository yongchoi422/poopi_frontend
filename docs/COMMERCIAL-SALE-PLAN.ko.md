# SOULI 1차 판매 조건 검토안

2026-10-03 · **420만 개·달력 마감 없음·50:50 사용자 확정. V2 고정 ETH 조건·배포·실제 소액 사이클 완료. 정식 판매 중지**

## 이번 사용자 결정

게임 완성 전에 기존 SOULI와 inscription을 판매하는 방향이다. 게임은 Cooking으로 공개한다. 기준 FDV는 15,000,000 USD, 총 공급은 210,000,000 SOULI다. 첫 판매 희망 규모는 약 200,000–300,000 USD다. 사용자는 90일 대신 **완판 기준, 달력상 마감 없음**을 선택했고, 실제 구매 ETH의 반은 LP·반은 운영에 사용하는 **50:50을 승인했다**. 총 판매 한도는 420만 개다.

앞서 LP 목표로 말한 50,000–100,000 USD는 ETH와 SOULI **양쪽 합계**였다. 매출 200,000–300,000 USD에서 ETH의 50%+맞은편 SOULI를 투입하면 총 LP는 200,000–300,000 USD가 되므로, 반반안은 이전의 작은 LP 목표를 확대하는 선택이다. 둘이 같은 안이라고 설명하지 않는다. 판매 ETH 100% LP 안도 현재 합의가 아니다.

Base ETH 결제, 즉시 SOULI 지급, 수동 Uniswap LP, 기존 A/B/C 중 어느 하나의 독립 운영을 유지한다. 원본 토큰이나 운영자의 다른 물량을 자동으로 인출하는 시스템이 아니다. 성공한 구매 후 계약상 환불 기능은 없다. 실패하면 토큰/대금 이동 전체가 되돌려지고 가스는 지출될 수 있다.

기존 V1은 그대로 보존했다. 새 `SouliEthSaleV2`와 `SouliThreeWalletControllerV2`는 `endsAt=0`을 달력 마감 없음으로 명시하며 총 4.2M 누적 한도를 유지한다. 개별 구매 견적은 짧게 만료된다. 정책 50:50은 termsHash에 포함되지만 ETH 분배/용도를 강제하지 않는다. 계약·클라이언트 143개 로컬 테스트와 원본 Base 상태의 로컬 fork 검증이 통과했다. V2 공개 배포와 원본 SOULI 소액 구매/회수 사이클은 완료했다. 외부 독립 감사는 아직 하지 않았다. 재고 재입금이나 재개로 누적 판매 한도를 초기화할 수 없다. 긴급 중지 권한과 가격/환율 점검도 유지한다.

고정 ETH 단가의 판매가 오래 계속되면 USD 환산 가격은 변한다. 임의 가격 변경은 하지 않는다. LP를 완판 전에 개설하려면 고정가 판매를 먼저 중지/종료하고, 남은 물량은 공개된 새 조건으로 별도 회차에서 처리하는 방안을 검토한다. 완판 목표와 임의 조기 종료 가능성을 혼동하지 않도록 출시 전에 운영 조건을 공개한다. 이번 한도를 넘는 추가 판매는 자동으로 열지 않는다.

지갑 한도는 전체 판매 한도와 같은 420만 개로 확정했다. 별도의 개인 제한은 없으며 재고가 충분하면 레벨 5 최소 250만 개도 구매할 수 있다. 실제 결과는 기존 inscription 상태와 전송 경로에 따라 달라진다. 출시 때 프리셋과 남은 재고를 일치시킨다. 레벨이 게임 참여권이나 게임 능력을 보장하지 않는다.

## LP 총규모와 운영비 계산

아래는 판매 단가와 ETH/USD가 동일하게 유지된 가정이다. 시세 예측이 아니다. SOULI 쪽 가치는 동일한 초기 풀 가격에서 평가한다.

| 기준 매출 | 구매자 SOULI | LP ETH 쪽 | 별도 LP SOULI | 양쪽 합계 LP | 운영 재원, 비용 전 |
|---|---:|---:|---:|---:|---:|
| $200,000 | 2,800,000 | $100,000 | 1,400,000 ($100,000) | $200,000 | $100,000 |
| $250,000 | 3,500,000 | $125,000 | 1,750,000 ($125,000) | $250,000 | $125,000 |
| $300,000 | 4,200,000 | $150,000 | 2,100,000 ($150,000) | $300,000 | $150,000 |

최대 판매와 같은 가격의 LP를 모두 준비하면 **판매 4,200,000 + LP 2,100,000 = 6,300,000 SOULI, 공급 3%**가 필요하다. 420만 개는 구매자가 사는 재고이고 LP용 210만 개는 별도다. 판매 계약에는 승인한 판매 재고만 넣는다. 2026-10-04 읽기에서 A 지갑의 확인 잔액은998개이므로 이 재고가 준비됐다고 표시하지 않는다. 실제 공급 지갑 소유 및 이전 약속 물량과 충돌하지 않는지 확인이 필요하다.

50:50은 **ETH 매출 사용 비율**이다. 기존 팀 15%는 **토큰 공급 배분 목표**로 별개다. 전체 토크노믹스에서 판매 2%와 LP 1%를 다른 항목과 중복 배정하면 안 된다. 메인 지갑 밖 11.03%라는 과거 스냅샷만으로 그 전부가 팀 소유임을 확인한 것은 아니다.

매출이 적으면 50% 규칙에서 LP도 작아진다. 예컨대 $100,000 매출이면 LP ETH $50,000 + SOULI $50,000 = 합계 $100,000이고 운영 재원은 $50,000이다. 비율은 최소 매출/LP 규모의 보장이 아니다. 사용자가 차액을 넣으면 운영자 추가 납입으로 따로 기록하며 고객 매출로 계산하지 않는다. 실패/미달 시 무기한 달성률 막대로만 보여주는 방식은 피하고 실제 잔액과 계획 변경을 공개한다.

30만 USD 매출에서 기존 15:85 안은 총 LP 90,000 USD/운영255,000 USD였고, 새 50:50 안은 총 LP300,000 USD/운영150,000 USD다. 같은 매출에서 더 많은 ETH 유동성을 확보하는 대신 운영 재원이 105,000 USD 줄어든다. 개발/보안검토/유지보수/마케팅/세금·예비비를 운영 재원 안에 맞출 수 있는지 먼저 예산을 작성한다. 반반 비율만으로 신뢰가 생기는 것이 아니라 실제 예치 영수증과 LP 회수권 공개가 필요하다.

## ETH 가격과 유동성의 실제 의미

ETH/USD 기준값을 E라고 하면 정수 SOULI 1개의 가격은 `ceil(10^18 / (14 × E))` wei다. 배포 직전 출처·시각·ETH/USD와 최종 정수 wei를 함께 보존한다. 환율 2,500/3,000/4,000의 예시는 `commercial-round-proposal.json`에 있다. 현재 시세나 승인된 단가가 아니며 기존 42개 pilot 단가를 새 계약에 무심코 복사하면 안 된다.

고정 ETH 계약은 환율이 움직여도 USD 매출/FDV가 고정되는 계약이 아니다. LP 투입 때 ETH가 변동했거나 기존 풀이 있으면 필요한 SOULI 수량과 최초 가격도 다시 검토해야 한다. 기존 풀의 가격·유동성, 토큰 호환성, 최소 수령량, 가스, 실제 LP 소유권을 검토한 거래만 서명한다. 기존 고정가 판매와 DEX를 동시에 유지하면 가격 차이가 차익거래 기회를 만들 수 있다.

새 50:50 안의 총 LP $300,000에서 ETH 쪽은 $150,000이다. 이는 전체 구매자가 판매 가격으로 나갈 현금을 뜻하지 않는다. 단순 수수료 없는 x*y=k 예시에서 최초 가치 $10,000어치 토큰 매도 후 순간 가격 하락은 기존 ETH reserve$45,000의 약33.1%와 비교해 새 reserve$150,000에서 약12.1%다. 실제 수수료·거래 순서·다른 유동성이 결과를 바꾼다. 이는 같은 초기 가격과 동일 크기 거래의 산술 비교이며 가격 상승/원금 보장이 아니다. [Uniswap의 풀/초기 비율 설명](https://developers.uniswap.org/docs/protocols/v2/concepts/pools).

## 사용자 화면과 영수증

- 홈: Meet my SOULI → 원본 inscription 확인/공유. 게임은 Cooking, 초기 2D 실험은 상세 링크로 제공한다.
- 구매: 실제 토큰·수량·수량에 따른 레벨 구간·예시 모습·고정 ETH 견적·가스·판매 기간·권한·LP/운영 배분을 확인한다. 모든 구매가 별도 NFT나 무조건 새 무작위 추첨을 만든다고 설명하지 않는다.
- 보유: 현재 `/soul/`을 사용한다. 지갑 연결은 공개주소 조회, 원본 그림 표시는 읽기만 한다. 온체인 Dynamic/Stable과 실제 계정의 상태를 구분한다. 1개부터 dot도 크게 보인다. 빈 계정은 빈 상태, RPC 장애는 오류로 표시하며 예시를 소유한 것으로 보여주지 않는다.
- 공유: 원본 전체 24×24, PNG/원본 SVG/링크/X 작성창. X로 이미지가 자동 첨부되거나 자동 게시된다고 말하지 않는다. 공유 링크는 seed 모습의 스냅샷이며 현재 소유권 증명이 아니다.
- 자금: 누적 고객 결제, 현재 판매 계약 ETH, 관리자 인출, 실제 LP 예치, 운영자 추가 납입, 운영 지출을 별도로 표시한다. ETH가 주소를 옮겼다고 매출이 늘거나 LP가 생긴 것이 아니다.
- 3D: `게임 기획 모아 분석하기`의 새 방향을 참고했다. 이 작업에서는 해당 스레드의 `output/game/room-v2`를 수정하지 않는다. 3D는 게임 표현이고 원본 2D inscription과 별도 자산 발행으로 혼동하지 않는다.

## 배포 전에 닫아야 할 항목

1. 승인된 수량/마감 정책/50:50을 바탕으로 실제 운영 예산, LP 시점·잠금 계약·수수료 권한 및 실패 시 공개 방식을 확정한다. 지갑 한도 420만 개와 첫 LP 생성 후 원금 1년 잠금 방향은 확정됐다. 판매 주체·연락/분쟁 처리·대상 지역을 명시할 자료도 필요하다. 이 문서는 법률 적합성 검토가 아니다.
2. `SALE-SECURITY-REVIEW.ko.md`의 내부 검토를 읽고 독립 검토에 넘긴다. 현재 외부 감사는 의뢰/완료하지 않았다. 세 지갑 중 하나가 해킹되면 전체 재고/대금 노출 가능성이 남는다.
3. A의 기존 MetaMask EIP-7702 위임 주소/코드 해시를 고정 검증하고 직접 type-2 CREATE 경로를 준비했다. 실제 Base 복제 환경에서 원본 토큰과 함께 통과했다. 새 위임 서명이나 릴레이는 사용하지 않는다. 실제 MetaMask 배포/receipt는 별도 확인해야 한다.
4. 가격 기준·시작 시각·끝 값0·nonce·termsHash·원본 토큰·A/B/C·코드 해시가 고정된 V2 검토 파일을 만든다. 미확정 `null`이 남아 있는 지금은 배포하지 않는다.
5. 사용자가 실제 MetaMask에서 최종 배포/유한 사용승인/재고 입금/판매 개방 거래를 서명한다. 처음에는 중지된 상태로 생성하고 주소/권한/조건/소스를 대조한 뒤 제한된 재고로 새 계약 소액 구매를 확인한다.
6. 최종 문구와 구매/관리 manifest를 같은 검토된 계약에 연결하고 공개 페이지/모바일 재접속/영수증/inscription을 확인한 후 일반 판매를 연다. 기존 pilot 완료는 새 계약 검증을 생략할 근거가 아니다.

현재 `/buy/`와 정식 mainnet 관리자 설정은 비활성, pilot은 중지·잔액 0이다. 이번 작업은 새 자산 거래나 공개 배포를 하지 않았다.

재현: `node scripts/plan-commercial-round.mjs`, `node scripts/test-commercial-plan.mjs`. 계산은 정확한 정수 wei로 보존하며 제안 파일은 배포 manifest로 사용할 수 없다.
