## 2. 중지 상태로 새 계약 배포

기존 배포 클라이언트의 정확한 review/nonce/chain/from/data 검증을 사용한다. A의 현재 위임은 검토된 주소·코드 해시가 일치할 때만 허용한다. 새 위임을 승인할 필요가 없는 direct type-2 배포다. MetaMask 최종 서명은 사용자 본인이 한다. 계정/nonce/조건이 바뀌면 후보를 다시 만든다.

확정 영수증에서 controller/child 주소, status, 생성 거래 및 런타임, 운영자 A/B/C, 원본 SOULI 주소, 단가/총한도/지갑한도/시작/무기한/termsHash가 일치해야 한다. 소스 검증 결과도 실제 배포 코드에 연결한다. 배포와 재고 승인/입고/판매 개방은 서로 다른 거래다.

## 3. 원본 토큰 소량 확인

큰 재고를 넣기 전에 현재 A의 소량 SOULI로 유한 수량 승인 → 입고 → 재개 → 별도 일반 지갑 구매 → inscription 확인 → 중지 → 미판매 회수 → ETH 수금 순서를 확인한다. 각 거래의 잔액, 누적 sold/proceeds, allowance, 영수증을 저장한다. 테스트 구매도 누적 한도를 소비하고 가격·조건은 사후 수정되지 않는다. 거래가 pending이면 중복 요청하지 않는다.
