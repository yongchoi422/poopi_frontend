# 첫 LP 원금 1년 잠금 실행안

2026-10-03. 사용자가 **첫 LP 생성 후 원금 1년 잠금** 방향을 승인했다. 아직 풀이나 잠금 계약을 만들거나 자산을 예치하지 않았다.

2026-10-03 23:43 KST 이후 재확인: 사용자는 LP 원금 1년 잠금을 유지하고, 판매대금 수금·50:50 예산 구분·유동성 공급을 수동으로 운영하는 방향을 확정했다. 기존 판매 V2를 자동 LP 계약으로 바꾸지 않는다. 이 결정은 LP가 이미 잠겼다는 뜻이 아니다. 아래 잠금 코드 후보의 호환성/해제 경계/수령권 검증, LP 실행 시점·만기 수령 주소의 명시가 남는다. 판매 controller의 A/B/C 권한은 별도 잠금 계약에 자동으로 이어지지 않는다.

## 비용을 줄이는 후보

Base의 Uniswap V2 SOULI/WETH 풀과 ERC-20 LP 토큰을 사용하는 방안을 우선 검토한다. 판매/출금은 기존처럼 수동이다. LP 잠금에는 별도 수수료 사업자 대신 **OpenZeppelin VestingWallet의 표준 시간 잠금 설정**을 후보로 둔다. duration=0, start=공개된 해제 시각이면 그 시각 전에는 토큰을 지급하지 않는다. 플랫폼 구독료가 없는 방식이지만 배포·예치·해제 가스는 필요하다. 2026-10-04 표준 코드 가져오기와 배포 후보 생성기를 구현했고, 8개 로컬 검사 및 실제 Base 상태의 V2 pair fork 검증이 통과했다. 실제 잠금 배포·자산 예치는 아직 하지 않았다.

LP 생성 영수증의 실제 블록 시각을 확인한 다음 **그 시각부터 최소 365일 이상인 고정 해제 시각**을 정한다. 잠금 배포 전에 정한 시각을 무작정 사용하면 LP 생성이 늦어져 약속한 1년보다 짧아질 수 있다. 풀 생성→잠금 완료 사이에는 미잠금 상태가 존재하므로 실제 잠금 입금 영수증 확인 전에는 웹에 “Locked”를 표시하지 않는다. 원자적 생성/잠금은 별도 구현이 필요한 선택지이며 현재 자동 기능으로 설명하지 않는다.

## 수령권과 수수료

- 표준 VestingWallet은 누구나 release를 호출할 수 있지만 지급은 그 계약의 **현재 owner(beneficiary)**에게 간다. 호출자에게 보내는 구조가 아니다.
- owner는 수령권을 이전할 수 있다. 수령권 이전이 해제 시각을 당기지는 않지만, “소유권도 영구 고정”이라고 홍보하면 틀리다. ownership 포기는 해제 후 지급 불능을 만들 수 있으므로 운영상 금지한다.
- 현재 판매 controller에는 임의 토큰 인출·임의 호출 기능이 없다. LP 수령자로 이를 설정하면 LP를 다시 사용할 수 없을 수 있다. 잠금 beneficiary는 별도로 검토한 수령 주소를 정한다.
- V2에서는 LP 몫의 거래 수수료가 풀 가치에 포함된다. 별도로 수수료만 꺼내기 어렵기 때문에 이 후보에서는 **LP 지분과 그 안에 누적된 수수료를 함께 잠근다**. 이를 운영비의 즉시 현금원으로 계산하지 않는다.
- Uniswap V3/V4의 포지션 NFT는 이 ERC-20 시간 잠금과 다른 자산이다. 이 후보에 NFT를 보내면 안 된다.

## 공개할 증거와 순서

1. 풀 factory/router/WETH 주소, 실제 SOULI, 기존 pool/reserve/가격을 확인한다. 같은 이름의 가짜 pair를 사용하지 않는다.
2. 고정가 판매를 먼저 중지한다. 누적 고객 결제의 50%와 별도 SOULI를 계산하고 운영자 추가 납입/forced ETH를 매출에서 분리한다.
3. 실제 풀 비율·최소 수령량·유효기한·가스·유한 승인을 검토하고 수동 LP 생성 거래를 서명한다.
4. 잠금 계약의 검증된 소스/생성 코드, beneficiary, duration=0, 실제 unlock UTC를 확인한다. 원금 1년 이전 release 불가, 수령권 이전 후에도 조기 지급 불가, 만료 후 정상 지급을 로컬/테스트넷에서 검증한다.
5. 실제 LP 토큰만 잠금 계약에 옮긴다. 발행된 LP 중 어떤 비율이 잠겼는지, 잔여 미잠금 LP가 있는지와 최소 영구 잠금분을 구분해 공개한다.
6. 웹에는 pair·잠금 주소·LP 수량·확인 블록·잠금 입금 영수증·정확한 해제 시각을 표시한다. 약속/준비/생성/잠금 확인 상태를 구별한다.

재고·금액·가격이 변하면 실행 계획을 다시 만든다. 별도 후속 예치가 같은 계약에 들어가면 기존 해제 시각을 따르므로, 모든 나중 예치까지 각각 1년 잠겼다고 설명하지 않는다. 필요하면 회차별 새 시간 잠금을 사용한다. 잠금은 가격 하락·거래 손실·토큰 관리자 권한·사이트 침해를 방지하는 보증이 아니다.

근거: [OpenZeppelin Finance / VestingWallet](https://docs.openzeppelin.com/contracts/5.x/api/finance), [Uniswap V2 pool 원리](https://developers.uniswap.org/docs/protocols/v2/concepts/pools), [Uniswap V2 유동성 제공과 최소 수령량](https://developers.uniswap.org/docs/protocols/v2/guides/providing-liquidity). 코드 후보는 저장소에 설치된 OpenZeppelin 5.6.1 기준이며, 이 문서가 해당 LP 구현에 대한 독립 감사를 대신하지 않는다.
