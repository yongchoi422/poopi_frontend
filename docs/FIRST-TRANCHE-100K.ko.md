## 처음 입고

사용자는 준비가 끝나면 직접 A 지갑으로 SOULI를 옮기기로 했다. 확인 당시 A의 잔액은 998 SOULI. 기존 잔액 전부를 판매에 쓴다면 첫 재고 1,399,999개를 맞추는 추가 송금은 1,399,001개다. 송금 직전 잔액을 재확인한다. 기존 보유자에게 약속한 물량은 판매 재고와 겹치지 않아야 한다.

1. 원본 SOULI를 **Base 메인넷** A 지갑 `0x4a4AA86208EcFdBACBaD551dF7baf5D3C84425BB`에 준비한다.
2. `https://souli.net/manage/`에서 A 연결 → Fill first 1.4M → Approve this amount → Deposit stock. 승인과 입고는 별도 거래다. 각 거래의 수량·controller 주소를 확인한 후 사용자 MetaMask 최종 서명이 필요하다.
3. 입고 receipt와 재고를 확인하고 Open sale 서명. 정식 `/buy/`는 같은 V2의 체인 상태를 검증한다.
4. LP용 700,000개는 **판매 계약 밖**에 별도 보관한다. 이번에는 LP 전송/잠금 거래를 요청하지 않는다.

## 판매하면서 추가 입고

- 추가 가능한 양 = 4,200,000 − 누적 판매량 − 계약에 남은 SOULI 정수 재고. 관리 화면이 최신 블록에서 계산하고 review/send 각각 다시 확인한다.
- 처음 140만 개 분량을 준비하면 이후 추가할 수 있는 합계는 280만 개다. 300만 개 전부가 아니라 총 420만 개까지만이다.
- 판매 중지 없이 유한 approve → deposit 가능. 한 번에 전량을 넣을 필요가 없다. 다른 운영자의 입고와 겹쳐 현재 한도를 초과하면 전송 직전 검사가 차단한다.
- 재고 0이면 구매 불가. paused=false 상태에서 재입고하면 별도 Open sale 없이 다시 구매 가능하다. 이미 pause했다면 입고 후 Open sale 서명이 필요하다.
- 140만 개는 정책상 첫 공급 목표다. 별도 온체인/개인 한도가 아니다. 판매 수량은 회수·재입고로 초기화되지 않는다.
- 직접 체인 호출/토큰 송금으로 과잉 재고를 넣을 수는 있으나 계약의 누적 구매 cap은 늘어나지 않는다. 관리 UI는 과잉 입고를 막는다.
- **추가 판매에도 50% LP / 50% 운영**을 유지한다. 첫 LP 예산 이후 매출이 자동으로 전액 운영비가 되는 것은 아니다.

## LP와 검토 상태

LP 실행일은 미정이다. 실행 전 고정가 판매를 중지하고 DEX 가격과 남은 재고를 검토한다. 잠금 수령자는 실제 잠금 계약 배포 전에 확정한다. 최초 잠금 입금부터 최소 365일, 실제 receipt/소유자/만기 공개 전에는 Locked라고 표시하지 않는다. 판매관리 3개 지갑 권한은 LP 잠금에 자동 적용되지 않는다.

외부 독립 감사는 사용자 결정으로 출시 필수조건이 아니다. 기존 내부 검토와 코드 일치, 실제 소액 거래, 테스트/fork 증거를 사용하며 외부 감사 미실시를 공개한다. 출시 준비 작업과 실제 재고 입고·판매 개방·LP 실행을 구분한다.
