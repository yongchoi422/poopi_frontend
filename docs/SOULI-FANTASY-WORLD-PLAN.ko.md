# SOULI — 작은 등불의 숲

2026-10-03 · 판타지 생활·탐험·날씨 방어 기획 v0.5

**현재 제작 방향 — 넓은 하얀 미니어처와 여러 소울:** 사용자가 하얀 미니어처 세계를 선택하고 더 큰 장소와 여러 주민을 요청했다. [새 로컬 초안](../output/game/room-v2/MINIATURE-README.ko.md)은 30×20 바닥, 전체 너비 화면, 확대·드래그·주민 따라보기와 다섯 샘플 소울을 제공한다. 두 명이 입구를 막고, 두 명이 안쪽 물감을 씻고, 한 명이 압력을 낮추며 방벽을 수리한다. 첫 물결을 막아낸 뒤 더 큰 무리에서 범람·복구가 생기는 협동 사건이다. 한 기기의 다섯 자율 주민이며 온라인 다인 게임은 아니다. 실제 ETH·구매 원본·클라우드 저장은 아직 연결하지 않았다. 아래 맨해튼/숲은 이전 실험으로 남긴다.

**현재 제작 방향 — 맨해튼 옥상 복원:** 사용자가 첫 랜드마크로 맨해튼·엠파이어스테이트빌딩을 선택하고, 침략자는 물들이고 소울은 씻어내며, 방벽이 뚫리면 물감이 한꺼번에 번지는 사건을 제안했다. [Above Manhattan 초안](../output/game/room-v2/ROOFTOP-README.ko.md)에 사각 옥상·랜드마크·자동 준비·압력 방벽·물감 파도·원래 타일 복원·조명 회복을 연결했다. 두 ETH 샘플은 보라색의 넓은 웅덩이와 산호색의 흩날리는 물감으로 행동까지 구분한다. 실제 시세는 미연결이고 두 방향 모두 회복할 수 있다. 작은 dot의 능력을 약하게 만들지 않는다. 옥상 다리는 연결 가능성을 보여주는 형태이며 지역 이동은 아직 없다. 아래 숲 기획은 장기 생활·저장·원본 원칙의 배경으로 남기고, 다음 시각·사건 검증은 이 옥상에서 진행한다.

**후속 진행(2026-10-03):** 사용자가 이 방향으로 진행하기로 했다. [첫 로컬 플레이 초안](../output/game/room-v2/GROVE-README.ko.md)에 탐험·시설 배치·안개/오로라 방어·귀환·IndexedDB 저장을 연결했다. 아래 전체 기획의 완료를 뜻하지 않으며, 실제 ETH 관측·계정 백업·공동 방어는 후속 범위다.

**최신 방향:** 사용자가 직접 시설을 배치하지 않는 완전 자동 생활을 요청했다. 초안은 탐험 16초 → 자동 준비 9초 → 방어 30초 → 귀환 5초 → 휴식 20초를 입력 없이 반복하도록 변경했다. 배치와 시작은 선택적인 수동 개입이다. 이 시간과 안개/오로라 교대는 관찰용 데모이며 아래의 장기 생활·실제 날씨 주기와 구분한다. 현재 장기 부재 처리는 진행 중 외출 한 번까지만 마무리한다.

**색 점령 실험:** 이어서 사용자가 스플래툰을 참고한 색 번짐·점령과 새 생물 모델·공격 효과를 요청했다. 최신 로컬 초안은 소울의 민트색과 생물의 보라색이 바닥을 덮어쓰며, 남은 점령 면적이 결과에 영향을 주는 규칙 v2다. [공식 설명](https://splatoon.nintendo.com/en/gameplay/)의 영역 칠하기 원리를 참고했고, 숲·소울·생물·공격 연출은 기존 프로젝트에 맞춰 직접 구현했다. 아래 장기 기획 중 등불 빛만으로 성공을 나누던 내용에는 이 실험이 추가된다. 실제 ETH·여러 지역 영구 점령·온라인 대전은 아직 구현하지 않았다.

**상태: 검토 가능한 권고안. 아래 수치와 새 기능은 구현·배포·상품 제공 약속이 아니다.** 기존 사용자가 동의한 원본 존중, 작은 dot도 동등하게 즐기기, 외형이 바뀌어도 추억 유지, 장기 부재를 벌주지 않기, 최소 서버 원칙을 이어간다. 이번 문서는 방 중심 제안을 야외 판타지로 발전시킨다. 기존 판매·계약·소유권 정책은 변경하지 않는다.

## 1. 추천하는 게임

> 작은 소울이 숲을 탐험하고 자기 거점을 꾸린다. 현실의 ETH 흐름이 하늘을 바꾸면, 준비해둔 시설과 소울이 그 날씨에 맞춰 등불을 지킨다.

장르는 **작은 3D 세계에서 즐기는 자동 탐험·거점 생활 게임**이다. 디펜스는 탐험에서 얻은 것을 실제로 활용하는 사건이다. 기본 모드에서는 소울이 탐험·시설 선택과 배치·방어 시작·귀환·휴식을 스스로 이어간다. 유저는 지켜보다가 원할 때 목적지, 시설, 생활 계획에 개입한다. 배치나 시작 버튼을 누르는 일을 진행의 필수 조건으로 두지 않는다.

커피가 중심이던 실내 생활은 숲에서 돌아와 쉬는 장면으로 남긴다. 첫 화면의 주인공은 집 밖의 작은 소울과 그가 넓혀가는 생활권이다. 처음부터 넓은 세계나 자유 채굴을 구현하기보다 거점과 가까운 숲의 관계를 완성한다.

가칭은 **작은 등불의 숲 / Little Lantern Grove**. 최종 제품명은 SOULI를 유지하고 부제만 시험한다.

### 왜 이 조합인가

| 방향 | 얻는 재미 | 핵심 부담 | 판단 |
|---|---|---|---|
| 실내 생활 관찰 | 캐릭터 애착, 짧은 코미디 | 사건이 반복되면 목표가 약해짐 | 귀환·휴식·앨범에 사용 |
| 자유 채굴·건설 액션 | 직접 발견하고 지형을 바꾸는 자유 | 지형 편집, 물리, 전투, 콘텐츠 제작과 조작 부담 | 향후 별도 실험 후보 |
| 웨이브 디펜스 중심 | 배치의 효용과 성공·실패가 명확함 | 소울이 전투 유닛으로만 보이고 반복 강화에 치우칠 수 있음 | 거점에 의미를 주는 주요 사건으로 사용 |
| 자동 탐험 + 거점 + 날씨 방어 | 발견→생활 변화→배치→방어→새 발견이 연결됨 | 세 활동을 한 순환으로 묶는 설계 필요 | 이번 권고안 |

테라리아를 언급한 맥락에서 가져오려는 감정은 ‘집 밖에 무엇이 있고, 발견한 것으로 내 터전이 달라진다’는 기대다. 자유 채굴·거대한 연속 월드·직접 전투를 모두 첫 버전의 요구사항으로 묶지는 않는다.

## 2. 유지할 다섯 원칙

1. **원본이 주인공이다.** 원본 24×24 전경과 색을 유지한다. 입체는 선택 가능한 표현이다. 원본 크기나 토큰 잔액으로 전투력을 정하지 않는다.
2. **선택은 선택 사항이며 눈에 보이는 차이가 있다.** 명령 없이도 생활이 이어진다. 개입하면 같은 시설도 어느 길에 놓았는지, 어디를 탐험하는지에 따라 장면과 결과가 달라진다.
3. **자리를 비워도 생활은 편안하다.** 굶주림·주민 사망·집 파괴·접속 연속 보상 소멸을 기본 루프로 쓰지 않는다.
4. **날씨는 새로운 상황을 만든다.** 상승과 하락 모두 발견과 대응을 제공한다. 가격 방향이 생산량·전투력·토큰 손익을 직접 결정하지 않는다.
5. **진지한 소울과 사소한 사건의 조합을 남긴다.** 장엄한 등불을 지키고 돌아온 소울이, 발견한 돌이 마음에 들어 문 앞에 하나씩 정렬하는 모습이 SOULI의 개성이다.

## 3. 세계와 화면

### 첫 생활권

| 구역 | 공간과 분위기 | 반복 행동 | 달라지는 것 |
|---|---|---|---|
| 등불 거점 | 큰 나무뿌리 아래 작은 집, 따뜻한 목재, 중앙 등불 | 쉬기·제작·시설 배치·방어 | 시설과 전리품, 소울의 자주 쓰는 자리 |
| 이끼 숲 | 큼직한 풀·버섯·얕은 물·오래된 표지석 | 채집·길 찾기·작은 발견 | 지름길, 식생, 발견 기록 |
| 뿌리 동굴 | 숲 아래 짧은 동굴 입구와 반짝이는 틈 | 초기에 입구 발견, 이후 탐험 확장 | 두 번째 탐험 목적지와 새 대응 도구 |

첫 검증은 **거점과 이끼 숲의 두 작은 장면**으로 한다. 동굴은 다음 장소를 기대하게 하는 입구로만 보이고, 완성된 동굴 지역은 후속 범위다. 기존 하늘·뿌리·수정·심연 아이디어는 이 생활권을 검증한 뒤 지역별 확장에 쓴다.

기본 카메라는 비스듬한 고정 시점이다. 소울 따라가기와 장면 전환으로 이동을 보여주며, 자유 카메라 조작은 필수가 아니다. 동시에 렌더링하는 지역은 하나로 제한한다. 집 내부는 기존 월넛 방을 줄여 귀환 장면에 재사용할 수 있다.

첫 화면에는 장면, 짧은 행동 문장, 다음 계획 진입만 둔다. 가방·기록·원본·날씨의 자세한 정보는 눌러서 연다. 제품 UI는 기존 방침대로 영어다. 차트나 지갑 금액이 세계 장면을 차지하지 않는다.

## 4. 처음 10분과 다시 방문했을 때

| 시점 | 유저가 보는 것 | 선택과 결과 |
|---|---|---|
| 0~1분 | 소울이 오래된 등불 옆에서 깨어나 주변을 조사 | 무료 샘플로 바로 체험. 지갑 연결은 이후에도 가능 |
| 1~3분 | 가까운 숲으로 갔다가 빛나는 씨앗을 발견 | 첫 탐험은 짧은 튜토리얼. 돌아온 씨앗을 거점에 심음 |
| 3~5분 | 소울이 하늘을 보고 등불과 바람종을 직접 놓음 | 지켜보거나 선택적으로 시험 배치·되돌리기. 개입하지 않아도 계속 진행 |
| 5~8분 | 자연 안개로 만들어진 연습 방어가 자동 시작 | 시설에 따라 적의 이동과 소울 행동이 달라짐. 실제 ETH 사건으로 표시하지 않음 |
| 8~10분 | 숲의 표지석이 밝혀지고 다음 길이 보임 | 소울이 다음 생활을 이어감. 원하면 경로 또는 생활 계획 변경 |
| 다음 방문 | 귀환의 한 장면과 달라진 거점 | 완료 팝업을 여러 개 띄우지 않고 대표 사건 하나와 다음 선택 하나 |

첫 방문부터 조작 없이 소울이 생활한다. 수동 모드는 명시적으로 선택하고 언제든 자동 생활로 돌아올 수 있다. 이미 시작한 사건의 입력은 모드 전환으로 바꾸지 않는다. 처음 열어본 순간에 재미가 나야 하므로 실제 ETH 급변이나 다음 날까지 기다려야 첫 디펜스를 볼 수 있게 하지 않는다.

## 5. 반복 플레이와 장기 목표

**탐험 계획 → 자동 이동·발견 → 재료와 기억을 가지고 귀환 → 시설 배치 → 날씨 사건 대응 → 새 길·행동 발견**으로 이어진다.

초기 조정값은 평상시 한 순환 30~60분이다. 생활 장면을 관찰할 때는 몇 초~수십 초 단위의 작은 행동이 이어진다. 이 시간은 테스트 값이며 정확한 방문 주기를 강요하는 약속이 아니다.

유저가 오래 붙잡고 있을 때의 재미는 배치 미리보기, 이미 발견한 지역 관찰, 사건 재연, 꾸미기다. 계속 열어두었다는 이유로 동일 경과 시간의 생산량을 늘리지 않는다. 목적지 변경은 다음 미시작 구간부터 적용한다.

| 진행 구간 | 목표 | 남는 변화 |
|---|---|---|
| 첫 세션 | 내 소울이 어떤 행동을 하는지 이해 | 첫 발견과 첫 시설 |
| 초기 몇 차례 방문 | 숲의 두 경로와 시설 간 관계 발견 | 지름길, 새 생활 행동, 날씨별 일화 |
| 그다음 | 다음 지역의 입구를 복구하고 생활권 확장 | 새로운 지역과 시설 조합 |
| 충분히 검증한 이후 | 이웃과 작은 연결 거점 만들기 | 공동 등불·방문·비동기 협력 |

하루 접속 횟수나 연속 출석을 필수 조건으로 두지 않는다. 목표는 ‘공격력 100에서 110’보다 ‘그동안 못 가던 뿌리 아래 길에 우리 소울이 들어간다’가 먼저 읽히는 것이다.

## 6. ETH를 날씨로 옮기는 규칙

### 첫 버전: 24시간 변화율 하나로 이해 가능하게

현재 코드와 같은 Coinbase Exchange ETH-USD의 24시간 기준값과 최신 거래 가격을 사용한다. 이는 해당 거래소의 ETH/USD 변화이며 전체 코인 시장이나 SOULI 가격이 아니다. 출처·관측 시각·갱신 상태를 날씨 상세에서 볼 수 있게 한다.

`변화율 = (최신 거래 가격 / 24시간 시가 - 1) × 100`

아래는 **새 기획의 조정값**이다. 현재 구현은 맑음·비·안개·빛 폭풍 네 종류이며, 완만한 상승의 금빛 바람은 새 제안이다.

| 관측 변화율 | 하늘·환경 | 탐험의 변화 | 방어의 변화 |
|---|---|---|---|
| -1% 초과, +1% 미만 | 평온 | 익숙한 길과 일반 발견 | 자연 사건·연습, 기본 배치 점검 |
| -4% 초과, -1% 이하 | 이슬비 | 물가와 버섯 주변에 다른 발견 | 젖은 길의 느린 적, 배수·등불 활용 |
| -4% 이하 | 깊은 안개 | 가까운 빛을 따라 뿌리 쪽으로 탐험 | 가까워져야 드러나는 그림자, 시야와 유도 |
| +1% 이상, +4% 미만 | 금빛 바람 | 씨앗과 부유물의 이동 경로 변화 | 빠르게 움직이는 작은 무리, 바람종 활용 |
| +4% 이상 | 오로라 | 숲 위쪽에 빛 조각과 일시적 풍경 | 빛에 끌리는 무리, 유도와 빛의 분산 |

상승은 무조건 쉬움, 하락은 무조건 손해라는 규칙을 두지 않는다. **안개는 가시성, 바람은 속도·경로, 오로라는 빛에 끌리는 행동**을 바꾼다. 상이한 날씨에서 시설의 쓰임이 달라져야 한다.

특정 날씨에서만 필수 재료가 나오지는 않는다. 종류별 발견을 더 자주 보여줄 수 있지만 기본 도감·필수 진행에는 다른 입수 경로가 있다. 몇 주 동안 안개가 없어도 다음 지역을 열 수 있다.

### 강도와 급변

첫 버전은 가격 변화의 절댓값을 낮음·보통·강함의 세 단계로 제한한다. ±4% 이상은 강함의 상한에 도달한다. -20%가 -4%보다 다섯 배 어려워지는 식으로 계산하지 않는다. 적의 기본 능력은 플레이어의 발견 단계와 선택한 도전 단계에서 정한다.

후속 버전에서 단기 변동성을 ‘돌풍’으로 추가할 수 있다. 24시간 상승률과 실제 변동성을 같은 지표로 부르지 않는다. 추가하려면 일정 간격 가격 기록과 충분한 표본이 필요하다. 거래량·SOULI 가격·복잡한 보조지표를 첫 버전에 한꺼번에 넣지 않는다.

### 흔들리지 않는 전환

- 전역 관측 간격: 5분. 경계에 걸렸다고 하늘을 매 요청마다 바꾸지 않는다.
- 새 상태 후보가 연속 두 관측에서 일치하고 기존 상태를 최소 15분 유지했을 때 전환한다. ‘두 번 관측’은 정확히 10분 지속을 증명한다는 뜻은 아니다.
- 경계 복귀에는 0.3%p 완충 구간을 둔다. 예: 안개 진입은 -4% 이하, 해제 후보는 -3.7% 초과. 아래 전이표를 출발점으로 사용한다.
- 한 전투가 시작되면 사용한 날씨·배치·규칙·난수를 고정한다. 도중 가격 변화는 다음 전투부터 적용한다.
- 동시에 여러 날씨 효과를 전투에 겹치지 않는다. 시각 전환과 판정 변경 시점을 분리한다.

| 현재 상태 | 상태를 벗어나는 후보 조건 | 후보의 목적 상태 |
|---|---|---|
| 깊은 안개 | 변화율 > -3.7% | 그 값에 해당하는 위 기본 구간 |
| 이슬비 | 변화율 ≤ -4% 또는 > -0.7% | 그 값에 해당하는 위 기본 구간 |
| 평온 | 변화율 ≤ -1% 또는 ≥ +1% | 그 값에 해당하는 위 기본 구간 |
| 금빛 바람 | 변화율 < +0.7% 또는 ≥ +4% | 그 값에 해당하는 위 기본 구간 |
| 오로라 | 변화율 < +3.7% | 그 값에 해당하는 위 기본 구간 |

조건을 만족하지 않으면 현 상태를 유지한다. 큰 변화가 생기면 중간 상태를 차례로 거치지 않고 해당 목적 상태를 후보로 잡는다. 관측 누락·피드 장애는 연속 후보 횟수를 끊는다. 최초 유효 상태는 기본 구간으로 정하고, 그 뒤 전환에만 연속 관측·최소 유지 시간을 적용한다. ‘자연 날씨 대체’는 이 실제 시장 상태와 별도 필드로 기록한다.

## 7. 모두에게 같은 하늘, 각자의 방어

**첫 공개 버전은 같은 관측 날씨를 공유하는 개인 거점**이다. 다른 플레이어와 같은 전장에 실시간으로 접속해 싸우는 구조는 후속이다. NPC나 공개 샘플을 실제 접속 중인 이웃처럼 표시하지 않는다.

날씨는 계속 관측하되, 각 플레이어의 주요 자동 방어는 최대 6시간에 한 번으로 제한한다. 기상 현상이 길게 이어진다고 몇 분마다 습격을 생성하지 않는다. 6시간은 방문 마감 시간이 아니고 같은 유형 사건의 중복을 제한하는 조정값이다.

경과 시간의 첫 방어 시작 지점에 해당하는 저장된 날씨를 사용하고, 이미 시작한 탐험을 끝내고 귀환하는 흐름 안에서 사건을 배치한다. 실제 가격이 어느 순간 변했다는 사실과 몬스터가 침입하는 게임 사건은 구분한다. 실제로 관측한 기상에서 파생된 창작 사건이라고 설명할 수 있어야 한다.

공동 방어를 추가할 때는 서버가 라운드 시작 시 참여 명단과 목표를 확정한다. 이후 들어온 사람이 목표를 올리지 않는다. 기여는 서버가 확인한 구간에만 부여하고 로컬 완료 기록을 그대로 공동 점수로 올리지 않는다. 기존 ‘마지막 검증 후 2시간’ 참여 규칙을 무단으로 무기한 기여로 바꾸지 않는다.

## 8. 날씨 관측을 끊기지 않게 하는 최소 서버

현재 `world-weather.mjs`는 이용자의 요청이 새 가격을 관측할 때만 새 사건을 만든다. 사람이 없을 때의 시장 이력을 항상 가지고 있지는 않다. ‘밤새 실제 ETH 날씨 속에서 소울이 살았다’고 표현하려면 이 빈 구간을 해결해야 한다.

권고는 **세계 전체에 관측 작업 하나를 두고 5분마다 기록**하는 것이다. 이용자 수만큼 스케줄러나 소울 시뮬레이터를 실행하지 않는다. 가벼운 예약 작업으로 날씨 기록만 남기고, 각 거점은 접속 시 그 기록을 읽어 필요한 구간만 계산한다. 이 문서는 해당 작업의 생성이나 배포를 실행하지 않는다.

- 30일 기준 관측 슬롯은 8,640회다. 기존 stats/ticker 두 요청 방식이면 재시도 전 외부 HTTP 조회는 월 약 17,280회다.
- 슬롯 ID·상호 배제·재시도 한도로 중복 관측을 억제한다. 실행 시간·로그·저장·네트워크 비용이 있으므로 ‘무료’로 확정하지 않는다.
- 최대 12시간 정산에 필요한 기록은 정상 5분 간격에서 144구간 정도다. 이전 상태의 경계값도 함께 받아 제한된 범위를 처리한다.
- 최근 상세 기록은 30일 보관을 출발점으로 잡고, 이미 앨범에 남긴 사건은 사용한 날씨 스냅샷을 사건과 함께 보존한다.
- 피드가 15분 넘게 낡거나 오류가 나면 시장 상태를 `unavailable/stale`로 표시한다. 이미 고정된 전투는 그대로 마무리한다.
- 기록이 없는 구간은 일반적인 자연 날씨로 처리한다. 현재 가격을 과거에 소급하거나 실제 폭락·폭등을 지어내지 않는다. 기본 진행량은 데이터 장애로 줄이지 않는다.
- 이후 가격 이력이 도착해도 이미 확정한 개인 사건을 다시 추첨하거나 보상을 재지급하지 않는다.

역사 캔들로 모든 빈 구간을 당연히 복원할 수 있다고 가정하지 않는다. 공급자 문서에도 이력의 불완전성·조회 제한이 있다. 첫 버전은 직접 저장한 관측 기록과 명시적인 자연 날씨 대체를 사용한다.

## 9. 디펜스의 실제 플레이

### 목표와 선택

현재 v2 초안의 주 목표는 **소울의 민트색 영역을 보라색보다 넓게 남기면서 등불을 지키기**다. 생물은 이동과 공격으로 보라색을 퍼뜨리고, 소울·등불·차임·달빛 그릇은 공격과 파동으로 민트색을 남긴다. 이미 물든 땅도 반대 색으로 덮을 수 있다. 민트색 위의 적은 느려지고 보라색 위에서는 조금 빨라져, 색이 전투의 결과와 다음 움직임에 함께 영향을 준다. 수동 조작 없이 소울이 움직이고 공격한다.

바닥 표시와 판정은 같은 606개 셀을 쓴다. 집은 점령 면적에서 제외한다. 종료 때 민트 면적이 보라보다 넓고 등불 빛이 남아 있으면 이번 숲을 지킨 것으로 기록한다. 색은 귀환·휴식 동안 남고 다음 외출에서 새로 시작한다. 장기 확장은 숲의 구역을 되찾아 풀·꽃·시설·생활권이 바뀌는 방향으로 검증하되, 이번 짧은 전투의 색을 영구 영토나 실제 자산 소유권으로 취급하지 않는다.

지킬 대상은 중앙 등불의 **이번 사건 동안의 빛**이다. 실제 토큰, 이미 지은 집, 영구 수집품은 피해 대상이 아니다. 유저는 자유로운 전투 조작 대신 두 접근로의 시설 위치와 구성으로 준비한다.

첫 전장은 접근로 두 개, 설치 지점 여섯 개, 활성 시설 세 개로 한정한다. 시설 네 종류 중 세 개를 골라 배치한다. 길을 완전히 막는 배치는 미리보기에서 거부하거나 통과 가능한 울타리로 처리한다. 실시간 자유 지형 편집은 넣지 않는다.

| 시설 | 평상시의 쓰임 | 방어의 쓰임 | 배치 고민 |
|---|---|---|---|
| 새싹 등불 | 탐험 길 표시·소울의 쉬는 자리 | 안개의 적을 일찍 발견 | 입구를 밝힐지, 거점 가까이를 밝힐지 |
| 바람종 | 떠다니는 씨앗 유도·주변 조사 | 짧은 주기로 무리를 밀거나 주의를 돌림 | 적이 모이는 구간에 놓기 |
| 뿌리 울타리 | 덩굴 정원·생활 경계 | 한 구간을 느리게 통과하게 함 | 다른 시설의 작동 시간을 벌기 |
| 달빛 그릇 | 빛 조각 수집·야간 풍경 | 한정된 충격을 흡수하거나 오로라 무리를 유도 | 보호와 유인 위치 사이의 선택 |

기본 시설은 플레이로 모두 열 수 있다. 초기 배치와 첫 방어는 무료 체험에서도 가능하다. 구매량에 따라 시설 슬롯을 무제한 추가하지 않는다.

### 적과 소울

| 존재 | 읽히는 행동 | 대응 |
|---|---|---|
| 이끼 먼지 | 느리게 같은 길로 모임 | 울타리와 바람종을 연속으로 사용 |
| 그림자 씨앗 | 안개 속에서 가까워져야 드러남 | 앞쪽 등불로 조기 발견 |
| 빛나방 | 밝은 물체 쪽으로 경로를 바꿈 | 달빛 그릇으로 중앙 등불에서 유도 |

날씨는 이 적들의 구성·행동 매개변수를 바꾼다. 첫 버전에는 날씨마다 별도의 몬스터 군단을 제작하지 않는다. 소울은 시설 사이를 오가며 불을 다시 밝히고, 위험한 순간에는 안전 지점으로 돌아온다. 작은 dot도 같은 기본 판정과 시설 사용 능력을 갖는다.

### 한 사건의 길이와 결과

- 자동 모드의 준비 상태에서는 소울이 날씨에 맞춰 시설을 골라 놓고 사건을 시작한다. 수동 모드를 선택하면 저장한 배치를 유지하고 유저의 시작을 기다린다. 두 모드 모두 진행 중인 전투의 입력은 보존한다.
- 첫 조정값은 **총 3분, 세 무리**다. 온라인에서는 원래 길이로 관찰하거나 핵심 장면만 볼 수 있다. 오프라인은 결정된 과정을 정산하고 20~30초의 대표 재연을 보여준다.
- 시작한 전투의 배치를 바꿔 이미 받은 피해를 소급 제거하지 않는다. 변경은 다음 사건에 적용한다.
- 등불이 충분히 밝게 남으면 안정, 일부 어두워지면 흔들림, 모두 꺼지면 안전하게 물러난 뒤 복구한다. 복구는 짧은 무료 생활 연출이며 유료 수리나 대기 결제를 요구하지 않는다.
- 기본 탐험·제작 진행은 유지한다. 좋은 방어는 작은 추가 발견, 지름길의 먼저 보기, 다른 사건 결말을 제공한다. 필수 지역·기본 시설을 실패로 영구 잠그지 않는다.
- 보너스 크기와 성공 기준은 플레이테스트에서 정한다. 최초 시뮬레이션에서는 빛 100으로 시작, 종료 빛 60 이상/1~59/0의 세 결과를 시험한다. 검증된 균형값으로 주장하지 않는다.

전략의 재미가 약하면 집 파괴를 추가하기 전에 시설의 대응 관계와 피드백을 개선한다. 하드 모드는 이후 자발적으로 고르는 별도 도전이며 기본 방치 생활의 조건이 아니다.

## 10. 계산과 재연이 같은 사건을 보여주기

개인 전투도 `eventId, rulesVersion, seed, weatherSnapshot, loadoutRevision, startedAt`을 고정한다. 같은 사건을 새로고침·다른 기기·빠른 재연으로 다시 계산해도 결과가 같아야 한다.

첫 솔버는 단순한 경로 노드와 일정한 논리 틱을 사용한다. 3분 사건을 1초 단위로 계산하면 180단계다. 렌더러의 30/60fps, 물리 엔진의 부동소수점 움직임을 결과의 기준으로 쓰지 않는다. 경로 거리·공격 순서·같은 시각의 처리 순서·난수 소모 순서를 버전으로 고정한다.

브라우저는 같은 이벤트 로그를 부드럽게 그린다. 핵심 재연은 로그 중 주요 시점을 압축한 표현이며 실제 녹화본으로 부르지 않는다. 재연 코드가 바뀌어 옛 사건의 재현이 어려우면 이미 저장한 결과·대표 이미지·일지를 유지하고 재생 불가를 조용히 처리한다. 적어도 지원 중인 사건 규칙 버전은 재생 가능하게 관리한다.

공동 점수나 공식 보상을 추가하면 이 솔버를 서버에서도 돌린다. 클라이언트가 업로드한 점수만으로 결과를 승인하지 않는다.

## 11. 성격, 생활, 판타지 코미디

원본 외형과 별도로 주민 프로필을 둔다. 성향은 공격력 등급이 아니라 행동 타이밍과 사건 선택에 영향을 준다. 기본 생존·진행 능력은 성향 때문에 불리해지지 않게 한다.

| 장면 | 판타지 행동 | 사소한 결말과 지속 흔적 |
|---|---|---|
| 숲 채집 | 엄숙하게 빛나는 씨앗을 운반 | 자기보다 작은 돌까지 옆에 정렬, 수집 습관 발생 |
| 안개 탐험 | 작은 등불을 들고 길을 찾음 | 자신이 놓은 표지석을 낯선 유적으로 조사 |
| 바람 | 떠다니는 씨앗을 끝까지 추적 | 거점 바로 뒤에 내려앉음, 새싹 한 개 생김 |
| 오로라 | 달빛을 정성껏 그릇에 받음 | 밤새 그릇 대신 옆 웅덩이를 지켜봄 |
| 방어 후 | 소울이 먼지를 밀어내고 등불 복구 | 작은 먼지 하나가 따라와 울타리 옆에 머묾 |
| 귀환 | 신비한 동굴 조각을 발견 | 멋진 받침대보다 편한 의자로 사용 |

사건은 독립된 영상 목록보다 앞선 행동이 다음 일화로 이어지는 연결로 만든다. 좋아하는 자리, 발견한 물건, 탐험 경로가 다음 선택에 쓰인다. 커피·쿠션 같은 기존 생활 연출은 휴식 장면으로 일부 재사용한다.

## 12. 재료, 성장, 원본 소유

첫 버전의 제작 자원은 두 종류로 시작한다: 일반 건축 재료인 가지·섬유 묶음, 시설 기능을 여는 빛 조각. 개별 이름·숫자는 UI에서 꼭 필요할 때만 표시한다. 발견품과 도감은 자원과 분리한다.

새 시설과 지역은 서로 다른 행동을 열어야 한다. 반복해서 숫자만 커지는 강화 단계를 먼저 늘리지 않는다. 기존 자원·진행을 새 자원으로 바꿀 때는 별도 마이그레이션과 보존 정책을 마련한다.

**토큰 한 단위마다 고유 캐릭터 한 개가 생기는 구조로 설명하지 않는다.** 실제 Dynamic/Stable inscription과 원본을 읽어 주민 외형에 연결한다. `residentProfileId`는 원본의 seed·extra와 분리한다. 외형이 바뀌어도 닉네임·집·성향·기억을 유지한다.

거래·잔액 변화가 게임 공격력이나 날씨 방어 기여량을 직접 높이지 않는다. 구매는 자동 전투나 로컬 저장과 별개의 지갑 승인 흐름이다. 프로필 백업과 모델 파일은 소유권 증명이 아니다. 원본 보유가 바뀌었을 때의 활성 사용 정책은 기존 제품 정책에서 별도로 확정하며, 기록을 지우는 기본 동작으로 처리하지 않는다.

## 13. 오프라인과 복귀의 정확한 규칙

| 상황 | 처리 |
|---|---|
| 몇 분 뒤 복귀 | 진행 중 작업과 동일 사건을 이어 정산 |
| 몇 시간 뒤 복귀 | 경과 시간·계획 변경 기록·관측 날씨로 제한된 구간 정산 |
| 12시간 이상 부재 | 제작·탐험 생산은 초기안 12시간까지. 그 이후는 생활 요약으로 표현 |
| 일주일 뒤 복귀 | 밀린 경보 없이 대표 사건 1개, 최대 3개 요약, 현재 평온한 거점 |
| 시계가 뒤로 이동 | 음수 경과 시간을 0으로 처리하고 이미 정산한 구간을 취소하지 않음 |
| 시계를 앞으로 조작 | 개인 로컬 진행의 한계로 취급. 이를 공동 점수·유료 권리로 승격하지 않음 |
| 날씨 이력이 없음 | 일반 자연 날씨, 기본 진행량 유지, 실제 시장 사건으로 표기하지 않음 |

12시간은 제안이며 현재 구현의 2시간을 이미 변경했다는 뜻이 아니다. 자동 방어는 정산 대상 12시간 안에서 최대 두 사건을 출발점으로 잡는다. 여러 결과가 있어도 대표 장면은 하나만 먼저 보여준다.

새 시설을 놓으면 이전 계획을 그 시각까지 정산한 뒤 새 배치 버전을 연다. 오늘 설치한 시설이 어제 전투에 사용되는 모순을 막는다. 미접속 뒤 새로고침을 반복해 보상을 다시 뽑지 않는다. 완료 사건 ID를 영속 보관한다.

## 14. 로컬 중심 저장과 최소 클라우드

| 데이터 | 로컬 | 클라우드와 검증 |
|---|---|---|
| 3D 소울 메시 | 원본·변환 규칙으로 생성, 재사용 캐시 | 기본적으로 유저마다 GLB를 저장할 필요 없음 |
| 방·시설 배치·개인 계획 | IndexedDB에 변경 시 저장 | 작은 스냅샷·버전 백업 |
| 개인 탐험·사건·생활 기억 | 로컬에서 정산, 사건 로그 저장 | 계정 간 복구용 백업. 서버 공인 성과와 구분 |
| 앨범 이미지·짧은 클립 | 로컬 저장·사용자가 파일로 내보내기 | 기본은 사건 정보 백업. 이미지 업로드는 선택·용량 제한 |
| ETH 기상 이력 | 필요한 최근 구간만 캐시 | 전역 관측 기록, 출처와 규칙 버전 |
| 지갑 인증·구매 권리 | 표시용 캐시 | 서버 인증·체인 또는 구매 원장 확인 |
| 공동 방어 결과 | 서버 결과의 화면 표현 | 서버 정산, 중복 지급 방지 |

개인 방의 대부분은 오프라인으로 작동한다. 소유권 최신 확인이나 공동 기능을 사용할 때만 해당 온라인 상태를 요구한다. RPC 장애를 보유 상실로 판정하지 않는다. 마지막 검증 시각과 재확인 필요 상태를 구분한다.

`localStorage`는 작은 설정에 한정하고 구조화된 저장·앨범은 비동기 IndexedDB를 사용한다. 브라우저 저장 용량 요청과 영속 저장 요청은 보조 수단이며 사용자 삭제까지 막는 보장이 아니다.

### 백업·여러 기기·업데이트

- 로컬 저장은 중요 행동 완료 시 즉시, 잦은 변경은 짧게 묶어 처리한다. 저장 실패를 저장 성공으로 표시하지 않는다.
- 클라우드는 변경이 있을 때만 묶어서 보낸다. 목표는 정상 플레이 중 최대 5분 간격의 작은 백업과 중요 변경 시 저장이다. 종료 이벤트의 업로드만 믿지 않는다.
- 한 기기를 활성 작성 기기로 두는 방식을 먼저 검증한다. `baseRevision`이 다르면 서버가 충돌을 알려 양쪽 사본을 보존한다. 자원 수량을 두 기기 값의 합으로 병합하지 않는다.
- 오프라인에서 두 기기를 썼다면 어떤 진행을 이어갈지 복구 화면으로 선택하게 한다. 부가 앨범의 중복 제거 병합과 게임 경제 상태의 교체를 구분한다.
- 지갑별 저장 공간을 분리하고 지갑 변경 시 다른 계정의 방이 덮어써지지 않게 한다. 다른 소유자에게 사적인 앨범을 자동 이전하지 않는다.
- 저장은 `schemaVersion`을 갖고 업데이트 전 사본을 남긴다. 기존 로컬 세계·클라우드 집을 덮어쓰지 않는 별도 버전에서 시작한다.
- 재다운로드 가능한 자산 캐시와 반드시 보존해야 할 세이브는 별도 저장소·수명 정책을 쓴다. 캐시 삭제가 세이브 삭제로 번지지 않게 한다.

개인 세이브를 서버에 백업했다는 사실이 치트 방지를 뜻하지는 않는다. 공식 순위·거래 가능한 보상·공동 결과를 나중에 추가한다면 그 상태를 처음부터 서버 검증 영역에 두어야 한다.

## 15. 3D 제작과 프로덕션 목표

미술은 깊은 녹색·짙은 목재·밝은 작은 빛을 중심으로 잡는다. 화면 전체를 밝고 낮은 채도로 채우지 않는다. 소울 주변에는 단순한 바닥과 적절한 명도 차이를 확보한다. 빗줄기·안개·반짝임이 얼굴과 도트를 가리지 않도록 효과량을 제한한다.

원본 앞면이 자주 보이도록 카메라와 이동 방향을 설계한다. 현재 입체 생성기는 앞면 도트를 유지하고 연결 윤곽에 두께를 주는 방식이다. 모든 원본의 자연스러운 뒷모습이나 팔다리 리깅이 자동으로 생긴 것은 아니다. 기울기·통통 뛰기·부유·소품 반응으로 의도를 표현하고 원본을 임의 해체하지 않는다.

성능 숫자는 아래 **개발 목표**이며 현재 달성 보고가 아니다.

| 영역 | 출발 목표 | 측정 조건 |
|---|---|---|
| 첫 장면 다운로드 | 압축 전송 8MB 이내 | 냉 캐시, 핵심 장면과 런타임. 후속 지역은 지연 로딩 |
| 프레임 | 중급 모바일 30fps, PC 60fps 목표 | 비·안개·최대 적·입체 소울을 동시에 표시한 실제 기기 |
| 렌더 복잡도 | 보이는 삼각형 약 10만 이하, draw call 약 120 이하 | 그림자 패스 포함 측정 후 조정 |
| 적과 효과 | 동시 적 12개 안팎, 입자 개수 상한 | 최대 상황에서 배터리·온도·프레임 확인 |
| 텍스처 | 모바일 GPU 텍스처 예산 약 64MB | 압축 형식 지원과 품질별 실제 사용량 확인 |
| 저장 | 화면 애니메이션과 저장 작업 분리 | 저장·복귀 정산 때 긴 프레임 정지 확인 |

시설 반복 메시를 재사용하고, 배경 조명은 구워두거나 단순화한다. 실시간 그림자는 핵심 한 개부터 시험하고 저사양은 접지 그림자로 대체한다. 화면 해상도 배율을 제한하고 품질을 단계적으로 낮춘다. 숨긴 탭에서는 렌더링을 멈추고 돌아올 때 시간으로 복구한다.

논리 정산·모델 생성이 길어지면 Worker로 이동하되 먼저 시간을 측정한다. WebGL 컨텍스트 유실, 화면 회전, 백그라운드 복귀, 저장 용량 부족을 실제 기기에서 검증한다. 효과 줄이기·움직임 줄이기·색과 모양을 함께 쓰는 신호를 제공한다.

## 16. 제작 범위와 순서

### A — 재미를 확인하는 플레이 초안

거점 1개, 숲 길 1개, 소울 1명, 시설 4종 중 3개 배치, 접근로 2개, 적 3종, 생활 사건 6개, 자연 날씨 연습과 안개·오로라 방어를 연결한다. 동굴은 입구만 표현한다. 기존 3D 방·소울 생성기를 재사용하고 새 거점 장면을 만든다.

관측 데이터와 분리한 개발용 날씨 선택으로 동일 배치의 차이를 비교한다. 모든 선택은 데모임을 표시한다. 실제 날씨 공급, 지갑 연동, 상점보다 먼저 **시설을 옮겼을 때 왜 결과가 달라졌는지 보이는가**를 확인한다.

완료 기준: 첫 탐험→시설 배치→두 날씨의 방어→귀환이 이어짐. 작은 dot·밝은 원본·어두운 원본에서 읽힘. 방치 자동 배치와 수동 배치의 차이를 설명할 수 있음.

### B — 다시 방문할 수 있는 로컬 베타

두 탐험 경로, 생활 사건 12개, 다섯 날씨, 버릇 2~3개, 버전 있는 저장·앨범·오프라인 정산을 연결한다. 냉 시작·재접속·세이브 업데이트·모바일 성능을 검증한다. 실제 ETH 전역 관측 기록을 연결하며 장애 구간 대체 규칙을 적용한다.

완료 기준: 며칠 후 복귀해도 대표 사건과 거점 변화가 일관됨. 재시작·시계 변화·새로고침으로 동일 사건이 중복 지급되지 않음. 실제 날씨와 데모·자연 날씨가 구분됨.

### C — 제한된 프로덕션 베타

계정 백업·복원·기기 충돌·소유 확인·저장 마이그레이션·운영 로그·비용 경보를 연결한다. 소규모 실제 기기 테스트와 최대 상황 부하 검증 후 공개 범위를 늘린다. 원본 구매 경로와 게임 생활 저장을 별도로 검증한다.

완료 기준: 저장 손실·권한 혼동·복귀 불일치가 해결되고 배포 실패 시 기존 세이브를 복구 가능. 실제 관측 작업의 장기 실행과 장애 처리가 확인됨.

### D — 검증 후 확장

뿌리 동굴 전체, 이웃 방문, 비동기 공동 등불, 추가 주민과 관계, 선택 도전 모드를 순서대로 검토한다. 실시간 PvP·자유 파괴 지형·거대한 절차 월드·수익형 토큰 보상·사용자별 생성형 영상은 첫 출시 범위에 포함하지 않는다.

날짜 약속보다 각 단계의 완료 조건을 우선한다. A가 재미없으면 C의 계정·과금을 확장하기 전에 A의 배치와 탐험을 고친다.

| 복귀 | 5분·12시간·7일·시계 변경 | 상한·요약·저장된 배치 구간 일치 |
| 여러 기기 | 오프라인 분기와 동시 저장 | 양쪽 사본 보존, 수량 합산 악용 방지 |

초기 관찰에서는 5~8명에게 설명 없이 한 순환을 경험하게 한다. 이는 사용성 문제를 찾는 표본이며 잔존율이나 시장성을 입증하는 규모가 아니다. 두 배치 중 무엇이 다른지, 소울을 다시 보고 싶은지, 하락이 벌칙처럼 느껴지는지를 질문한다.

다음 단계는 수십 명의 여러 날 체험이다. 자발적 재방문, 첫 발견·첫 배치까지 걸린 시간, 사건 재연·앨범 이용, 저장 복구 성공, 가격 정보만 보고 떠나는지 등을 함께 본다. 재미가 검증됐다고 말할 기준은 실제 관측 후 확정한다.

## 19. 비용과 범위 관리

24×24 소울 자동 입체화에는 AI API 호출이 필요 없다. 새 비용 요인은 야외 장면 다운로드·선택적인 이미지 백업·전역 관측·계정 동기화다. 사용자별 전투를 서버에서 계속 실행하지 않는 구조를 유지한다.

이전 추산은 1인당 하루 2~5MB 전송 가정이었다. 야외 지역을 추가하면 냉 시작 용량·신규 방문자 비율·캐시 무효화에 따라 달라지므로 그 예산을 그대로 보장하지 않는다. 지역별 다운로드를 측정하고 이전 [계산 파일](../output/game/cost-estimate-2026-10-03/estimate.json)에 새 값을 넣어 다시 계산한다.

운영 초기에 가장 먼저 측정할 것은 ①첫 방문/재방문 전송량 ②API의 실제 실행 시간 ③저장 쓰기와 백업 크기 ④전역 관측의 중복 여부 ⑤모바일 GPU 부하다. 상시 서버를 줄이는 것과 유저 기기의 배터리를 과하게 쓰지 않는 것을 함께 최적화한다.

## 20. 다음 제작에서 고정할 제안

- 야외 판타지 거점을 기본 화면으로 한다. 기존 실내 방은 귀환과 휴식에 쓴다.
- 탐험·시설 배치·방어 시작·휴식은 기본적으로 자동이다. 직접 배치와 생활 계획 변경은 선택적인 개입이다. 직접 채굴·실시간 액션은 이후 별도 검증 대상으로 둔다.
- 실제 ETH는 날씨를 정하고, 날씨는 경로·행동·방어 전략을 바꾼다. 기본 성장량은 시장 방향에 종속시키지 않는다.
- 개인 세계를 먼저 완성하고 공동 방어는 서버 검증과 함께 확장한다.
- 첫 플레이 초안의 판단 장면은 **명령 없이 숲에서 발견 → 소울의 자동 준비 → 방어 → 귀환과 휴식 → 다음 외출**이다. 같은 날씨에서 수동 개입의 차이도 비교한다.

이 제안은 사용자 최종 선택을 대신하는 확정 공지가 아니다. 구현 착수 때에도 아직 결정되지 않은 상품·토큰 정책을 같이 변경하지 않는다.
