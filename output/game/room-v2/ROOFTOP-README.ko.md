# SOULI — Above Manhattan

2026-10-03. 숲의 자동 생활과 색 점령 실험을 **작은 소울이 도시의 원래 색을 되찾는 자동 청소 사건**으로 발전시킨 로컬 플레이 초안이다. 사용자가 제안한 맨해튼 옥상, ETH에 따른 물감 변화, 방벽 붕괴 후 넓게 퍼지는 물감을 함께 구현했다.

## 열기

이 디렉터리에서 `npm install`, `npm start` 후 <http://127.0.0.1:4318/rooftop.html>. 기존 숲은 `grove.html`, 월넛 방과 원본 입체화 실험은 `room.html`에 남아 있다. 저장도 각각 분리한다.

## 이번에 확인할 감정

> 물감이 쌓인다. 방벽이 버티다 터진다. 바닥이 한꺼번에 물든다. 작은 소울이 진지하게 수습한다. 어느새 타일이 드러나고 도시의 불이 돌아온다.

손실과 전투력 경쟁보다, 작은 캐릭터와 큰 소동의 대비를 본다. 작은 dot와 큰 원본의 플레이 능력은 같다. 구매량이나 원본 크기로 방벽이 더 쉽게 무너지지 않는다. 원본의 눈·얼굴·픽셀을 재창작하지 않는다.

## 실제 플레이

기본은 자동이다. 옥상 둘러보기 16초 → 도구 준비 9초 → 방문자와 청소 30초 → 귀환 5초 → 휴식 20초를 반복한다. 배치나 시작 클릭은 필요 없다. 논리상 3분 사건을 6배속으로 보여주는 관찰용 시간이다. `Arrange it myself`에서 선택적으로 배치를 바꾸거나 사건을 시작할 수 있다.

방문자가 양쪽 입구로 들어온다. 방벽이 닫혀 있으면 입구에 모이면서 물감 압력이 쌓인다. 압력계가 차고, 방벽이 흔들리며, 뒤의 웅덩이가 넓어진다. 한도를 넘으면 그 방벽은 한 번 열린다. 각 방벽에서 물감 파도가 논리상 7초, 화면상 약 1.17초에 걸쳐 옥상 안쪽으로 퍼진다. 이 파도는 실제 청소 면적을 바꾸는 사건이다. 단순 화면 효과가 아니다.

붓 울타리는 해당 방향 방벽의 압력 한도를 30에서 44로 높인다. 이 초안의 기본 두 배치에서는 두 방벽이 모두 터지도록 조율했다. 처음부터 실패하지 않는 방어를 만드는 것보다 예고→붕괴→수습을 한 번 경험하도록 한 것이다. 반복 사건마다 강도·성공 조건을 달리하는 장기 밸런스는 후속 작업이다.

소울과 세 시설이 자동으로 물감을 씻는다. 민트색은 씻는 순간의 물방울·파동이고, 바닥에는 원래 크림색 타일이 드러난다. 깨끗한 바닥을 민트로 새로 칠하지 않는다. 옥상 조명은 청소 비율에 따라 켜지며, 데모의 정리 목표는 80%다. 미달해도 소울·집·소유 자산이 사라지지 않는다.

사건 결과의 물감과 열린 방벽은 귀환·휴식 동안 유지된다. 다음 외출에는 새 사건의 바닥과 방벽으로 돌아온다. 여러 날에 걸친 영구 도시 복원은 아직 없다.

## ETH와 물감

| 비교 버튼 | 이 초안의 모습 | 행동 차이 |
|---|---|---|
| ETH ↓ 4.2% / Violet drizzle | 보라 물감, 서늘한 도시 하늘 | 느린 방문자, 넓은 자국과 웅덩이 |
| ETH ↑ 4.2% / Coral confetti | 산호색 물감, 따뜻한 하늘 | 빠른 나방, 더 멀리 흩어지는 작은 물방울 |

**둘 다 고정 샘플이며 실제 ETH 가격이 아니다.** 화면에 DEMO와 시세 미연결을 표시한다. 준비 전에 버튼으로 비교할 수 있고, 시작한 사건은 날씨·샘플 변화율·배치·난수·규칙 버전을 고정한다. 중간 새로고침이나 다른 설정으로 기존 결과를 바꾸지 않는다. 자동으로 다음 외출을 시작하면 두 시나리오가 번갈아 온다.

양쪽 모두 원래 장소를 회복할 수 있다. 가격 하락을 소울 약화나 토큰 보상 감소와 연결하지 않는다. 실제 피드 연결 시에는 [장기 기획](../../../docs/SOULI-FANTASY-WORLD-PLAN.ko.md)의 관측 시각·이력·전이 완충·강도 상한·피드 장애 규칙을 먼저 적용해야 한다.

## 장소와 모델

사각 옥상, 크림 타일, 낮은 벽과 난간, 목재 물탱크, 작은 관리실, 휴식 공간, 화분, 전구, 주변 건물과 계단식 랜드마크를 코드로 모델링했다. 엠파이어스테이트빌딩은 [공식 건축 설명](https://www.esbnyc.com/about/architecture-design)의 Art Deco와 첨탑 실루엣을 참고한 축소 해석이다. 사진·상용 모델·텍스처를 가져오지 않았다. 실제 건물의 정확한 복제나 공식 제휴 콘텐츠가 아니다.

좌우 다리는 다음 옥상으로 이어질 형태만 제시한다. 지금은 지역 이동·연결 지도·다른 사용자 방문이 없다. 장소별 표면과 복원 결과가 충분히 읽히는 것을 확인한 다음, 남산 등 두 번째 장소로 확장한다.

생물은 숲 실험의 뿔 씨앗·기어오는 버섯·날갯짓 나방 세 모델을 재사용하고 날씨에 맞춰 색을 바꾼다. 다음 모델링 순서는 **압력을 만드는 덩어리 → 넓게 묻히는 생물 → 작게 흩뿌리는 비행 생물**이다. 이 장면의 역할과 실루엣을 먼저 구분하고, 디테일·표정·파열 애니메이션을 다듬는다.

## 실행·저장 범위

- 바닥의 동일 면적 셀을 논리 계산과 표시가 공유한다. `2`는 물감, `1`은 씻긴 곳, `0`은 손대지 않은 곳이다. 점수는 셀 수로 계산하고 둥근 외곽은 표시상 보간이다.
- 사건당 방문자 20개, 논리 프레임 181개. 효과는 입자 320개·원 80개·물감 파도 메시 10개로 제한한다. 정적 배경은 재질별 병합, 반복 요소와 생물은 인스턴싱, 픽셀 비율 상한 1.5, 렌더 목표 30fps를 사용한다.
- `Still`에서는 입자와 입체 파도를 바닥 원으로 줄인다. 실제 이동과 청소 판정은 계속된다.
- 저장 DB는 `souli-manhattan-prototype-v1`. 숲의 `souli-grove-prototype-v1`을 덮어쓰지 않는다. IndexedDB, revision 비교, 중복 정산 방지, 최근 24개 기억, JSON 내보내기를 재사용한다.
- 장기 부재는 진행 중이던 한 번만 끝내고 쉰다. 닫힌 브라우저 안에서 계속 실행하거나 오프라인 사건을 무제한 생성하지 않는다.
- 실제 시세 API·게임 서버·AI 모델링 API를 호출하지 않는다. 계정·지갑·구매 원본·백업/가져오기·온라인 협동은 연결하지 않았다.

이것은 독립된 로컬 초안이다. 기존 구매 사이트·계약·배포를 변경하지 않으며, 실제 기기 성능·복구·권한·실제 관측 이력 검증을 마친 프로덕션 게임으로 안내하지 않는다.

## 코드와 확인

| 파일 | 역할 |
|---|---|
| `rooftop.html` | 옥상 UI, 비교용 날씨, 압력 안내 |
| `rooftop-world.mjs` | 옥상·랜드마크·방벽·조명 모델과 카메라 |
| `rooftop-surface.mjs` | 바닥 셀, 오염/세척 판정, 두 샘플 날씨 |
| `rooftop-combat.mjs` | 압력·붕괴·범람·청소의 결정적 사건 계산 |
| `grove.mjs`, `grove-rules.mjs`, `grove-store.mjs` | 기존 순환·입력·저장 공유. 옥상 v3, 기존 숲 v1/v2 유지 |
| `grove-paint.mjs`, `grove-creatures.mjs` | 풀링한 효과와 생물 모델, 장소별 색 적용 |
| `test-rooftop.mjs` | 압력/범람, 실제 바닥 복원, 양 날씨 회복, 고정 입력, 중복/오프라인 결과 |
| `verify-rooftop.cjs` | 브라우저 자동 순환·효과·새로고침·조명·두 날씨·모바일·저장 분리 |

`node --test test-grove.mjs test-rooftop.mjs`로 기존 19개와 새 6개 규칙을 검사한다. 서버 실행 후 `node verify-rooftop.cjs`, 이어서 `node verify-grove-color.cjs`로 실제 WebGL과 기존 숲을 확인한다. 브라우저 검증은 순서대로 실행한다. 결과는 `rooftop-verification.json`과 `grove-color-verification.json`, 검수 화면은 `rooftop-*.png`다. Playwright 경로는 이 Codex 환경의 번들 경로이며 소프트웨어 WebGL 결과를 실제 휴대전화 FPS로 해석하지 않는다.

이번 확인에서 규칙 25개가 통과했다. 옥상 브라우저 검증은 클릭 없는 첫 사건, 실제 압력·범람 효과, 중간 재로드, 휴식 중 열린 방벽 유지, 날씨 입력 고정, 상승 시나리오 전환, 저동작 모드, 320/390px의 가로 넘침 없음, 숲과의 저장 분리, 콘솔 오류 없음을 확인했다. 기본 하락 배치는 75.6% 깨끗한 바닥으로 시작해 두 방벽이 터진 뒤 최종 90%와 전구 16개 회복으로 끝났다. 이는 고정 난수·기본 배치의 초안 결과이며 전체 조합의 성공 보장이 아니다.

기존 숲의 색 점령 브라우저 회귀도 통과했다. 마지막 모바일 검수에서는 중복 상태 표시를 줄이고, 두 너비에서 첨탑이 HUD 아래에 가리지 않고 표시되는 것을 별도로 확인했다.
